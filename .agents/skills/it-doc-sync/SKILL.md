# IT Portal 문서 거버넌스

## 핵심 원칙

문서가 코드와 운영 계약을 정확히 설명하게 하고, 같은 사실을 여러 문서에 복제하지 않는다. 루트와 변경 대상 저장소의 `CLAUDE.md`를 먼저 읽고 코드·설정·테스트·마이그레이션·스크립트에서 사실을 확인한다.

문서 품질 개선은 코드 변경 권한이 아니다. 사용자가 요청한 문서 모드와 저장소 범위만 수행하며, 진단 요청에서는 파일을 수정하지 않는다.

## 실행 모드

| 모드 | 수행 범위 |
| --- | --- |
| 점검 | 문서 인벤토리를 만들고 코드와의 불일치, 누락, 중복, 잘못된 위치, 고아 문서와 인덱스 누락을 근거와 함께 보고한다. 파일은 수정하지 않는다. |
| 현행화 | 경로, 명령, 계약, 예제, 주석을 현재 구현에 맞추고 더 이상 유효하지 않은 설명을 제거하거나 올바른 SoT로 연결한다. |
| 표준화 | 문서별 역할과 SoT를 적용하고 제목·용어·링크·인덱스 구조를 일관되게 정리한다. 의미 없는 전면 재작성이나 서식 통일은 하지 않는다. |
| 개선 | 독자가 작업을 수행하는 데 필요한 탐색성, 설명 순서, 예제, 실패 조건과 체크리스트를 보강한다. 코드에서 확인할 수 없는 주장은 만들지 않는다. |
| 전체 | 점검 → 현행화 → 표준화 → 개선 → 검증 순으로 수행한다. 각 단계의 미해결 항목과 제외 범위를 남긴다. |

사용자가 모드를 지정하지 않으면 요청 문구에서 필요한 최소 모드만 선택한다. `점검`, `검토`, `진단`은 읽기 전용이며 `현행화`, `정리`, `표준화`, `개선` 요청만 해당 문서를 수정할 권한을 준다.

## 문서 역할

루트와 대상 저장소의 `CLAUDE.md`가 아래 분류보다 우선한다.

| 위치 | 기록할 내용 |
| --- | --- |
| `README.md` | 사람을 위한 설치·실행·구조 개요·배포·문제 해결 |
| `CLAUDE.md` | 반복 적용할 필수 규칙, 금지 사항, 검증 진입점 |
| `docs/guides/` | 여러 변경에서 재사용하는 구현 계약, 절차, 예제, 체크리스트 |
| `docs/operations/` | 날짜와 환경이 있는 배포·복구·인계·실행 결과 |
| `docs/superpowers/` | 설계는 `specs/`, 구현 계획은 `plans/`, 완료분은 각 하위 `done/`. 실행 근거는 `evidence/`, 조사 메모는 `notes/`, 종합 리포트는 `reports/` |
| `docs/clean-code-review-YYYY-MM-DD.md` | Clean Code 진단 리포트. 완료된 `done/` 기록이 이 평면 경로를 참조하므로 하위 폴더로 옮기지 않는다 |
| `docs/db-schema-gap/`, `docs/test/` | 날짜별 DB Gap 리포트와 테스트 결과 리포트 |
| `docs/artifacts/` | 보고·공유용 생성 산출물과 그 인덱스 |
| `it_database/docs/verification/` | 특정 DB 변경을 검증하는 실행 가능한 SQL |
| `AGENTS.md` | `CLAUDE.md`로 향하는 포인터와 절 바로가기. 규칙 본문을 두지 않는다 |
| `.agents/skills/` | 반복 워크플로우의 canonical 스킬. `.claude/skills/`는 얇은 어댑터만 둔다 |
| `TASK.md`, `TASK_DONE.md` | 검증된 활성 과제와 완료 근거 |
| `versions.lock` | 함께 검증된 하위 저장소 리비전 조합 |
| `meta/backlog.md` | 운영 적용 대기 중인 DB 변경의 상태 관리 |

`agents(db).md`는 개발자 로컬 DB 접속 설정이므로 인벤토리와 현행화 대상에서 제외한다. 내용을 다른 문서로 옮기거나 비밀값을 인용하지 않는다.

제품 의도는 `prds/`, 엔티티·컬럼 명명은 `meta/`, 물리 데이터 모델은 `it_database/migrations/`를 우선한다. 구현이 다르다는 이유만으로 제품 요구사항이나 적용된 마이그레이션을 문서에 맞춰 덮어쓰지 않는다.

## 워크플로우

1. 요청에서 실행 모드, 대상 저장소, 문서 종류와 수정 권한을 확정한다.
2. 루트와 대상 저장소의 `CLAUDE.md`, 가장 가까운 `docs/guides/README.md`를 읽는다.
3. 대상 범위의 README, CLAUDE, 가이드, 운영·검증 기록, TASK와 소스 주석을 인벤토리로 만든다. 적용되지 않는 문서 종류는 제외 이유를 기록한다.
4. 각 주장을 코드·설정·테스트·마이그레이션·빌드 파일·스크립트와 대조한다. 현재 Git 변경이 있으면 다른 작업의 변경을 사실 기준선으로 오인하지 않는다.
5. 각 사실을 하나의 SoT에만 두고 다른 문서는 링크한다. 반복 규칙과 날짜성 실행 기록을 섞지 않는다.
6. 교차 저장소 계약이 관련되면 다음 연결을 함께 확인한다.
   - 백엔드 DTO·OpenAPI → 프론트 `codegen`, 생성 타입과 소비 코드
   - DB 마이그레이션 → 백엔드 엔티티, 데이터 모델 가이드와 검증 자료
   - 함께 검증된 하위 저장소 리비전 → 루트 `versions.lock`
7. 요청된 문서만 최소 범위로 수정하고 원래 인코딩과 유효한 구조를 보존한다.
8. 완전성·링크·사실관계 검증을 실행하고 실패나 확인 불가 항목을 숨기지 않는다.

## 주석과 코드 품질 경계

- 신규·수정 JavaDoc, TSDoc와 인라인 주석은 한글로 작성한다.
- 공개 API, 서비스 메서드, composable 반환 함수의 입력·출력·실패 조건이 코드만으로 명확하지 않으면 누락된 설명을 보강한다.
- 자명한 대입과 구현을 그대로 번역한 주석은 추가하지 않는다. 실제 동작과 어긋난 주석은 정정하거나 제거한다.
- TODO/FIXME는 후속 조치가 가능한 문장으로 작성하고 장기 과제는 코드 근거와 중복 여부를 확인한 뒤 `TASK.md` 후보로 제시한다.
- 비즈니스 로직은 변경하지 않는다. 문서 조사 중 발견한 코드 결함은 위치·영향·재현 근거를 보고한다.

요청이 문서뿐 아니라 코드 품질 진단을 명시하면 `it-clean-code-audit`, 테스트 보강이나 품질 게이트를 명시하면 `it-test-maintenance`, 운영 DB와 로컬 DDL 차이를 명시하면 `it-db-gap`, 마이그레이션 작성·적용·복구를 명시하면 `it-db-migration`을 해당 범위에 함께 적용한다. 문서를 코드와 대조한다는 이유만으로 다른 스킬을 자동 실행하지 않는다.

## 검증 체크리스트

- 대상 범위의 재사용 가이드가 가장 가까운 가이드 인덱스에서 탐색 가능하며 고아 문서와 인덱스 누락이 없다.
- 수정한 로컬 링크, 파일 경로, 절 참조와 명령이 존재한다. 안전하고 범위에 맞는 명령은 직접 실행하고, 실행하지 못한 명령은 미검증으로 표시한다.
- 버전, API 경로, 설정 키, 환경 이름, 생성 타입과 예제가 현재 SoT와 일치한다.
- 동일한 규칙이나 설명이 README, CLAUDE와 가이드에 중복되지 않는다.
- 시점성 수치와 실행 결과가 규칙 문서에 고정되지 않고 적절한 운영·리포트 문서에 있다.
- 문서와 예제에 비밀번호, 토큰, 개인정보 또는 운영 본문이 새로 노출되지 않는다.
- 변경 diff를 다시 읽어 사용자나 다른 작업의 변경을 덮어쓰지 않았고 요청 범위 밖의 의미 변경이 없는지 확인한다.

사용자가 병렬 에이전트 사용을 명시하면 백엔드, 프론트엔드, 실패 처리 탐지를 독립 범위로 나눌 수 있다. 그렇지 않으면 현재 세션에서 직접 수행한다.

## 종료 조건

- 요청한 저장소와 문서 종류가 모두 인벤토리에 포함되었거나 제외 이유가 기록되었다.
- 변경하거나 문제로 보고한 사실마다 현재 코드·설정·테스트 또는 공식 SoT 근거가 있다.
- 깨진 링크, 고아 가이드, 중복 SoT와 확인되지 않은 명령이 남으면 완료로 표현하지 않고 잔여 항목으로 보고한다.
- 발견한 코드 결함은 문서 수정으로 숨기지 않고 별도 후속 과제로 분리한다.

## 결과 형식

- 선택한 모드, 대상 저장소·문서와 제외 범위
- 변경한 파일 또는 발견 사항과 현재 SoT 근거
- 이동·통합·링크 처리한 중복과 인덱스 변경
- 실행한 검증, 성공·실패·미검증 결과
- 수정하지 않은 코드 결함과 후속 스킬·과제

## 흔한 실수

- README와 CLAUDE에 같은 설명을 복사한다.
- 점검 요청인데 문서를 바로 수정하거나 전체 모드를 임의로 실행한다.
- 인덱스에 연결된 문서만 보고 실제 디렉터리의 고아 문서를 놓친다.
- 코드에서 확인하지 않은 계획을 구현 사실처럼 기록한다.
- 파일 수·테스트 수·완료 날짜 같은 시점성 수치를 규칙 문서에 고정한다.
- 문서 현행화 범위에서 비즈니스 로직까지 고친다.
