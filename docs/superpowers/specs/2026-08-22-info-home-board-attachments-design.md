# 정보 홈 게시판 첨부파일 표시 설계

## 목표

정보 홈의 공지사항과 게시판 기반 주요 일정에서 실제 첨부파일을 표시하고, 게시판 목록과 같은 아이콘·다운로드 경험을 제공한다.

## 데이터 흐름

- 공지사항과 일정 게시물을 조회한 뒤 `flNbr > 0` 또는 `flApgYn === 'Y'`인 게시물 번호만 모은다.
- 공통 파일 일괄조회 API에 `pkColNm=공통게시판`과 게시물 번호 목록을 전달한다.
- 응답 중 `flTpCone === '첨부파일'`인 파일만 각 공지·일정의 `attachments`에 연결한다.
- 첨부 조회 실패가 공지·일정 자체를 오류 상태로 바꾸지 않도록 본문은 유지하고 첨부 목록만 비운다.
- 협의회 일정은 게시판 게시물이 아니므로 첨부파일을 조회하거나 표시하지 않는다.

## 화면 동작

- 첨부파일 1~2개는 파일 확장자별 `FileFormatIcon`을 표시한다.
- 각 아이콘에 마우스를 올리면 파일명을 표시하고, 클릭하면 인증 쿠키를 사용하는 Blob 다운로드를 시작한다.
- 첨부파일 3개 이상은 게시판 목록과 같은 클립 아이콘·개수 배지를 표시한다.
- 개수 배지를 클릭하면 `AppDialogHeader`와 `AppDialogFooter`를 사용하는 표준 첨부파일 목록 다이얼로그를 연다.
- 다이얼로그는 개별 다운로드와 선택·전체 ZIP 다운로드를 제공한다.
- 공지 행은 제목 링크와 첨부 액션을 분리해 버튼 안팎의 클릭이 게시물 이동과 섞이지 않게 한다.
- 주요 일정의 남은 기간 배지는 현재처럼 오른쪽 끝에 유지한다.

## 오류와 접근성

- 다운로드 실패는 기존 게시판 번역 문구를 사용하는 오류 Toast로 알린다.
- 아이콘 버튼은 파일명 또는 첨부 개수를 포함한 접근성 라벨을 가진다.
- 다운로드 버튼 클릭은 상위 링크·행 이벤트로 전파하지 않는다.

## 검증

- composable 단위 테스트로 일괄조회 대상, 파일 연결, 첨부 조회 실패 격리를 검증한다.
- 공통 컴포넌트 단위 테스트로 1~2개 직접 다운로드와 3개 이상 다이얼로그 진입을 검증한다.
- 정보 홈 페이지 테스트로 공지·일정에 공통 첨부 액션이 연결되고 협의회 일정에는 표시되지 않는지 검증한다.
- 관련 단위 테스트, 타입 검사, 포맷 검사, 핵심 Playwright 시나리오를 실행한다.
