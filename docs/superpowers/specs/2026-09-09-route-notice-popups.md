# 화면별 작성 안내 팝업 설계

## 목적

공통 안내와 세 화면의 작성 안내를 `TPRMPP_BGDOCM` 문서로 관리하고, 대상 화면 진입 시 한 개의 전역 다이얼로그에서 순차 노출한다.

## 팝업 매핑

- `common.popup`: 모든 인증 화면의 공통 안내
- `common.info`: `/info/projects/form`에서 `ordinary=true`가 아닌 정보화사업 작성 안내
- `common.ordn`: `/info/cost` 경상사업 작성 안내
- `common.cost`: `/info/projects/form?ordinary=true` 전산업무비 작성 안내

사용자가 지정한 식별자와 경로의 대응을 그대로 적용한다.

## 동작

- 공통 안내와 화면 안내가 함께 적용되면 공통 안내를 먼저 표시하고 닫은 뒤 화면 안내를 표시한다.
- 공통 안내는 앱 셸 세션에서 한 번 처리하고, 체크하지 않고 닫은 화면별 안내는 대상 화면을 벗어났다가 재진입하면 다시 표시한다.
- `오늘 하루 보지 않기`를 체크하면 브라우저 현지 날짜의 다음 자정까지 해당 콘텐츠 버전을 숨긴다.
- 같은 날 관리자가 내용을 변경하여 콘텐츠 버전이 바뀌면 다시 표시한다.
- 조회 실패나 미등록 안내는 업무 화면 진입을 막지 않는다.
- 전역 다이얼로그는 `AppShell`에 한 번만 마운트한다.

## 관리

기존 안내 팝업 관리 화면에서 `common.popup`, `common.info`, `common.ordn`, `common.cost`를 각각 조회, 저장, 게시 중지할 수 있게 한다. 사용자 API와 관리자 API는 서버 허용 목록에 든 네 식별자만 받는다.
