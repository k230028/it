# 메뉴 트리·경로·링크메뉴 통합 설계

- 작성일: 2026-08-09
- 상태: 사용자 승인
- 대상 화면: `/admin/menus`, `/admin/routes`, 공통 헤더·사이드바 메뉴

## 1. 목적

관리자 메뉴 트리의 탐색성과 유형 식별성을 높이고, 게시판을 별도 메뉴유형 없이 페이지화면으로 통합한다. 경로 카탈로그가 내부 경로와 외부 URL을 함께 관리하도록 확장하며, 링크메뉴는 등록된 외부 URL을 새 창으로 연다.

## 2. 범위

### 포함

- 메뉴 트리의 모두 펼치기, 부분 접기, 모두 접기
- 부분 접기 시 2단계 메뉴까지만 표시
- 메뉴그룹·링크메뉴·페이지화면의 시각적 구분
- 게시판 메뉴유형 `BRD` 제거와 기존 데이터의 `PGE` 전환
- 페이지화면의 화면경로 선택지에 활성 게시판 경로 포함
- 경로 카탈로그의 외부 `http(s)` URL 등록 지원
- 링크메뉴 생성·수정 활성화와 새 창 이동
- 관련 DB 마이그레이션, 백엔드 검증, 프론트 테스트

### 제외

- 링크 열기 방식의 사용자별 설정
- `http(s)` 이외 스킴(`mailto:`, `tel:`, 사용자 정의 스킴)
- 게시판을 경로 카탈로그 테이블에 영구 동기화하는 별도 배치
- 메뉴 최대 깊이 4단과 권한·숨김·정렬 정책 변경

## 3. 확정된 설계 결정

### 3.1 경로 카탈로그 재사용

별도 경로유형 컬럼을 추가하지 않는다. 경로 값의 형식과 메뉴유형의 조합으로 의미를 결정한다.

| 메뉴유형 | 허용 경로 | 동작 |
| --- | --- | --- |
| `GRP` | 없음 | 하위 메뉴를 담는 그룹 |
| `PGE` | `/`로 시작하는 내부 경로 또는 활성 게시판 경로 | 현재 포털 탭에서 이동 |
| `LNK` | 경로 카탈로그에 등록된 `http(s)` 절대 URL | 새 브라우저 창/탭에서 이동 |

`BRD`는 더 이상 유효한 메뉴유형이 아니다. 게시판은 `/board/{게시판관리번호}`를 화면경로로 갖는 `PGE` 메뉴로 표현한다.

### 3.2 게시판 경로의 원천

정적 내부 화면과 외부 URL은 `TPRMPP_CMENUD` 경로 카탈로그에서 관리한다. 게시판 경로는 게시판 메타데이터에서 동적으로 만든다. 게시판 생성·사용여부 변경 때마다 경로 카탈로그 행을 동기화하지 않는다.

메뉴 관리 화면의 `PGE` 화면경로 선택 목록은 다음 두 원천을 합친다.

1. 사용 중인 내부 경로 카탈로그 항목
2. 사용 중인 게시판을 변환한 `게시판명 (/board/{게시판관리번호})` 항목

중복 경로가 생기면 하나만 표시한다. 게시판 경로는 게시판 이름을 우선 라벨로 사용한다.

## 4. 메뉴 트리 동작

PrimeVue Tree의 `expandedKeys`를 페이지 상태로 관리한다.

- **모두 펼치기**: 자식이 있는 모든 노드 키를 펼침 상태로 만든다.
- **부분 접기**: 루트 노드만 펼침 상태로 남겨 1·2단계 메뉴만 보이게 한다. 3·4단계는 접힌다.
- **모두 접기**: 펼침 상태를 모두 제거해 루트 메뉴만 보이게 한다.

세 버튼은 직원검색 조직도 툴바의 크기·아이콘·배치 패턴을 따른다. 버튼 라벨은 `모두 펼치기`, `부분 접기`, `모두 접기`로 통일한다. 트리 재조회 후 현재 펼침 키 중 존재하지 않는 키는 제거한다.

## 5. 메뉴유형 표현

승인된 A안을 적용한다. 색상만으로 의미를 전달하지 않고 배경색, 아이콘, 유형 텍스트를 함께 사용한다.

| 유형 | 아이콘 의미 | 유형 텍스트 | 시각 방향 |
| --- | --- | --- | --- |
| `GRP` | 폴더/그룹 | 그룹 | 파란 계열의 옅은 배경과 강조 텍스트 |
| `LNK` | 외부 이동 | 링크 | 보라 계열의 옅은 배경과 외부 링크 표시 |
| `PGE` | 문서/화면 | 화면 | 녹색 계열의 옅은 배경과 화면 표시 |

기존 메뉴 아이콘 `imkNm`은 메뉴 자체의 대표 아이콘으로 유지한다. 유형 아이콘과 유형 텍스트는 관리 트리에서 구조를 설명하는 보조 표시이며 `imkNm`을 덮어쓰지 않는다. 왕관과 연결 끊긴 게시판 경고도 기존처럼 함께 표시한다.

## 6. 경로 관리 화면

`/admin/routes`는 내부 화면과 외부 링크의 공통 경로 카탈로그로 명확히 보이도록 문구를 조정한다.

- 화면 제목: `경로 관리`
- 경로 컬럼: `경로`
- 이름 컬럼: `경로명`
- 각 행에 `내부화면` 또는 `외부링크` 태그 표시
- 신규 입력 안내: 내부 경로 예시 `/budget/list`, 외부 URL 예시 `https://example.com`

경로 기본키는 기존과 같이 수정하지 않는다. 신규 행만 경로를 입력할 수 있고 기존 행은 이름·사용여부·비고만 수정한다. 참조 중인 경로의 삭제 금지 정책도 유지한다.

## 7. 메뉴 편집 화면

### 7.1 페이지화면

`PGE`를 선택하면 `화면경로` Select에 내부 경로와 활성 게시판 경로만 표시한다. 게시판을 별도 필드로 고르는 UI와 `BRD` 전용 상태·경고는 제거한다.

### 7.2 링크메뉴

`LNK`를 선택하면 `외부 URL` Select에 사용 중인 외부 URL 경로만 표시한다. 외부 URL은 `/admin/routes`에서 먼저 등록해야 한다. 선택지 라벨은 `경로명 (URL)` 형식으로 보여 동일한 도메인의 경로를 구분한다.

### 7.3 유형 변경

메뉴유형을 바꾸면 이전 유형의 경로를 즉시 비운다. 유형과 경로가 맞지 않는 숨은 값이 저장 요청에 남지 않게 한다.

저장 버튼은 다음 경우 비활성화한다.

- 루트 메뉴가 `GRP`가 아닌 경우
- `PGE`에 화면경로가 없는 경우
- `LNK`에 외부 URL이 없는 경우

## 8. 백엔드 검증

### 8.1 경로 형식

`AdminRouteService`는 경로를 다음 두 형식 중 하나로 검증한다.

내부 경로:

- 단일 `/`로 시작
- `//`로 시작하지 않음
- 공백 없음
- URI 스킴 없음

외부 URL:

- Java URI 파싱 성공
- 스킴은 대소문자 구분 없이 `http` 또는 `https`
- 호스트 존재
- 사용자정보(`user:password@host`) 없음
- 공백 없음

`javascript:`, `data:`, 프로토콜 상대 URL, 호스트 없는 URL, 일반 상대 경로는 거부한다.

### 8.2 메뉴유형과 경로 조합

`AdminMenuService`는 다음 규칙을 강제한다.

- `GRP`: 경로 없음
- `PGE`: 경로 카탈로그의 사용 중인 내부 경로이거나 사용 중인 게시판 경로
- `LNK`: 경로 카탈로그의 사용 중인 외부 URL
- 그 밖의 유형: 거부

게시판 PGE는 기존 `BRD`와 동일하게 사용 중인 게시판만 저장할 수 있다. 메뉴 조회에서도 `/board/{번호}` 형식의 PGE가 미사용·삭제 게시판을 가리키면 사용자 트리에서 숨긴다. 관리 트리에는 남겨 관리자가 경로를 바꾸거나 삭제할 수 있게 한다.

## 9. 사용자 메뉴 이동

메뉴 노드 단위 탐색 헬퍼를 둬 헤더와 사이드바가 같은 규칙을 사용한다.

- `PGE`: 기존 내부 탐색을 사용한다.
- `LNK`: `target="_blank"`, `rel="noopener noreferrer"`가 적용된 외부 링크로 연다.
- 그룹이 접힌 사이드바에서 첫 하위 메뉴로 이동할 때도 첫 대상 노드의 유형을 확인한다.
- 외부 링크는 현재 포털 라우트, 활성 헤더, Breadcrumb, 탭 목록을 변경하지 않는다.

사이드바의 모든 깊이에서 외부 링크 표시를 동일하게 적용한다. 새 창 열기가 브라우저 정책으로 차단되더라도 현재 포털 화면은 이동하지 않는다.

## 10. 데이터베이스 마이그레이션

새 Flyway 마이그레이션은 다음 순서로 동작한다.

1. 활성 메뉴의 `MNU_TP_C='BRD'`를 `PGE`로 변환
2. 공통코드 `MNU_TP_C/BRD`를 soft delete 처리
3. `CK_CMENUM_TP` 제약을 `GRP`, `LNK`, `PGE`만 허용하도록 재생성

`SRE_PTH` 컬럼은 메뉴와 경로 카탈로그 모두 300자로 외부 URL 저장에 충분하므로 스키마 컬럼을 추가하거나 확장하지 않는다. 이미 적용된 과거 마이그레이션은 수정하지 않는다.

## 11. 오류 처리

- 경로 형식 또는 메뉴유형 조합 오류는 백엔드가 구체적인 400 메시지로 반환한다.
- 중복 경로는 기존처럼 409로 반환한다.
- 참조 중인 경로 삭제는 기존처럼 409로 반환한다.
- 메뉴·경로 관리 화면은 기존 Toast와 재조회 실패 배너 패턴을 유지한다.
- 선택 가능한 경로가 없으면 해당 Select 아래에 등록 또는 활성화가 필요하다는 안내를 표시한다.

## 12. 테스트 전략

### 백엔드

- `AdminRouteServiceTest`: 내부 경로와 안전한 `http(s)` URL 허용, 위험·비정상 URL 거부
- `AdminMenuServiceTest`: `GRP/PGE/LNK` 조합, 경로 카탈로그 사용여부, 게시판 PGE 검증
- `MenuQueryServiceTest`: 비활성 게시판 PGE 숨김과 일반 PGE·LNK 유지
- OpenAPI 계약 테스트: 메뉴유형 허용값에서 `BRD` 제거

### 프론트엔드

- 메뉴 트리 펼침 상태: 전체 펼침, 2단계 부분 접기, 전체 접기
- 관리 트리 유형별 A안 클래스·아이콘·텍스트
- `PGE` 선택지: 내부 경로와 활성 게시판만 포함
- `LNK` 선택지: 외부 URL만 포함
- 유형 변경 시 경로 초기화와 저장 비활성화
- 사이드바 모든 깊이와 헤더 첫 대상 이동에서 LNK 새 창 속성 검증
- 기존 드래그앤드롭·권한·재조회 실패 테스트 회귀

### 데이터베이스와 통합 검증

- 마이그레이션 소스 또는 검증 SQL로 `BRD` 잔존 행·활성 공통코드·제약 허용값 확인
- 프론트 Health Stack: `npm run format:check`, `npm run check`, `npm run lint:css`, `npm test`, 관련 E2E
- 백엔드 Health Stack: `./gradlew test`, `./gradlew check`, 필요 시 `./gradlew integrationTest`
- 두 서버를 기동한 뒤 `/admin/routes`, `/admin/menus`, 사용자 사이드바를 브라우저로 확인

## 13. 완료 기준

1. 메뉴 트리 툴바 세 버튼이 동작하고 부분 접기는 2단계까지만 표시한다.
2. 관리 트리에서 세 메뉴유형이 A안으로 식별된다.
3. 관리자 경로 화면에서 안전한 외부 URL을 등록할 수 있다.
4. PGE는 내부·게시판 경로만, LNK는 외부 URL만 선택할 수 있다.
5. 기존 BRD 메뉴가 PGE로 전환되고 신규 BRD 저장 경로가 사라진다.
6. 링크메뉴가 모든 사용자 메뉴 깊이에서 새 창으로 열린다.
7. 비활성 게시판 메뉴가 사용자 트리에서 노출되지 않는다.
8. 관련 단위·계약·마이그레이션 검증과 Health Stack이 통과한다.
