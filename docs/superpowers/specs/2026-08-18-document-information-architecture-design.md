# 저장소 문서 정보구조 정리 설계

## 목적

루트와 `it_backend`, `it_frontend`, `it_database`의 문서를 독자와 수명에 따라 분리한다. 같은 정책을 여러 문서에서 설명하지 않고 한 문서를 단일 출처로 삼아, 에이전트 컨텍스트 비용과 문서 현행화 비용을 함께 낮춘다.

## 문서별 책임

- `CLAUDE.md`: 작업자가 반드시 지킬 저장소 고유 규칙, 금지 사항, 비자명한 함정, 변경별 검증 명령만 둔다.
- `README.md`: 사람을 위한 소개, 사전 준비, 빠른 시작, 구조 개요, 배포 진입점, 문제 해결과 상세 문서 링크를 둔다.
- `docs/guides/`: 반복해서 참고하는 구현법, 설계 배경, 계약, 예제와 체크리스트를 둔다.
- `docs/operations/`: 날짜, 배포 상태, 복구 절차, DBA 인계처럼 특정 변경에 귀속되는 기록을 둔다.
- `TASK.md`: 아직 완료되지 않은 기술부채와 후속 과제만 둔다.
- `docs/superpowers/`: 승인된 설계와 구현 계획을 보관한다.

## 저장소별 설계

### 루트

루트 `CLAUDE.md`는 4-repo 토폴로지, SoT 지도, 공유 워킹트리 안전 규칙, 공통 코딩·보안 원칙, Health Stack에 집중한다. 설치·접속·운영 절차는 루트 README와 각 저장소 문서로 연결한다.

### 백엔드

백엔드 `CLAUDE.md`는 레이어 경계, Oracle/JPA 함정, 인증·권한의 강제 규칙, 변경 시 함께 갱신할 계약과 검증 명령을 유지한다. 배경과 사용 예시는 `docs/guides/{architecture,persistence,security,integrations,operations,domains,conventions}`로 보낸다. 날짜가 있는 파일 정규화 배포 기록은 `docs/operations/`로 이동한다.

### 프론트엔드

프론트엔드 `CLAUDE.md`는 API 래퍼 선택, 인증 책임, 상태 경계, UI/i18n 강제 규칙과 검증 명령을 유지한다. 상세 상태 모델과 예제는 기존 주제별 가이드가 담당한다. 루트에 남은 이동 안내 파일은 정식 경로 참조를 확인한 뒤 제거한다.

### 데이터베이스

데이터베이스에는 저장소 전용 `CLAUDE.md`와 `docs/guides/README.md`를 만든다. README는 설치·빠른 시작·가져오기/내보내기 진입점으로 재구성하고, 마이그레이션 작성 규칙과 운영 절차를 가이드와 운영 문서로 분리한다.

## 안전성과 호환성

- 기존 미커밋 변경은 덮어쓰지 않고 현재 워킹트리 내용을 기준으로 편집한다.
- 비밀번호를 명령행이나 문서 예시에 넣지 않는다.
- 적용된 Flyway 스크립트 수정 금지와 운영 이력 재작성 위험 경고를 유지한다.
- 내부 Markdown 링크가 모두 존재하고, 모든 활성 가이드가 인덱스에 노출되게 한다.
- 3줄짜리 이동 안내 파일은 저장소 내부 참조가 없을 때 삭제한다.

## 검증

- 문서의 상대 Markdown 링크 존재 여부 검사
- 각 `docs/guides/README.md`와 실제 가이드 파일의 인덱스 일치 검사
- 삭제한 이동 안내 경로의 잔여 참조 검사
- 문서에 기록한 명령과 경로를 `package.json`, Gradle 설정, 애플리케이션 설정, 마이그레이션 디렉터리와 대조
- 네 저장소의 diff를 각각 검토해 기존 사용자 변경이 보존됐는지 확인
