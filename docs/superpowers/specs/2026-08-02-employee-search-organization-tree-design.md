# 직원 검색 조직 트리 동기화 설계

## 목적

직원 검색 및 결재권자 검색에서 직원 행을 단일 클릭했을 때 좌측 조직 트리가 해당 직원의 소속 조직을 가리키도록 동기화한다. 조직 트리의 아이콘과 들여쓰기 규칙도 실제 계층 구조에 맞게 일관되게 표시한다.

## 범위

- 공통 `EmployeeSearchDialog`에 적용하여 모든 사용처가 동일한 동작을 사용한다.
- 직원 단일 클릭은 하이라이트와 조직 트리 이동만 수행한다.
- 최종 선택 확정은 기존과 동일하게 직원 더블클릭 또는 `[선택]` 버튼으로 수행한다.
- API 계약이나 백엔드 동작은 변경하지 않는다.

## 설계

### 직원과 조직 트리 동기화

`OrgUser`에 서버 응답에 이미 포함된 소속 부점 코드 `bbrC`를 명시한다. 직원 행을 클릭하면 다음 순서로 처리한다.

1. 클릭한 직원을 하이라이트한다.
2. `bbrC`와 일치하는 조직 노드를 전체 조직 트리에서 찾는다.
3. 해당 노드의 모든 상위 조직을 펼친다.
4. 좌측 선택 키와 우측 브레드크럼 경로를 해당 조직으로 갱신한다.
5. 조직 검색 필터 때문에 대상이 숨겨져 있으면 필터를 해제한다.
6. 렌더링 후 대상 조직 행을 좌측 트리 스크롤 영역 안으로 이동한다.

직원 클릭에 따른 조직 동기화에서는 직원 목록 API를 다시 호출하지 않는다. 재호출 시 현재 직원 하이라이트가 초기화되고 선택 버튼이 비활성화될 수 있기 때문이다. 직원의 `bbrC`가 없거나 조직 트리에서 찾을 수 없으면 기존 부서 선택을 유지하고 직원 하이라이트만 적용한다.

### 조직 아이콘

루트 조직은 기존 `pi-building`을 유지한다. 하위 부서를 하나 이상 가진 모든 조직은 깊이와 관계없이 현재 전무이사 노드에 쓰이는 `pi-sitemap`을 사용한다. 자식이 없는 조직은 기존 깊이별 표현을 단순화하여 `pi-users`를 사용한다.

### 깊이 들여쓰기

`lvl0`부터 `lvl3`까지만 지원하던 클래스 기반 제한을 제거한다. 각 노드의 실제 `depth`로 CSS 사용자 정의 속성을 설정하고, 기본 좌측 여백과 단계별 간격을 계산하여 5단계 이상의 조직도 동일한 간격으로 계속 들여쓴다.

## 구조

트리 탐색, 경로 및 상위 키 계산, 아이콘 결정, 들여쓰기 값 계산은 순수 유틸리티로 분리한다. `EmployeeSearchDialog`는 이 유틸리티를 사용해 화면 상태와 DOM 스크롤만 담당한다. 기존 조직 선택 시 직원 목록 조회 흐름은 유지한다.

## 오류 및 예외 처리

- 직원의 소속 부점 코드가 누락된 경우 현재 트리 상태를 유지한다.
- 조직 데이터에 해당 코드가 없는 경우 현재 트리 상태를 유지한다.
- 기존 조직 및 직원 조회 실패 알림 동작은 변경하지 않는다.
- 조직 스크롤 대상 DOM이 아직 없더라도 선택 상태 갱신은 정상 완료한다.

## 테스트

- 자식이 있는 조직이 깊이와 무관하게 `pi-sitemap`을 반환하는지 검증한다.
- 0~5단계 이상의 깊이에서 들여쓰기 값이 계속 증가하는지 검증한다.
- 조직 코드로 대상 노드, 경로, 상위 조직 키를 찾는지 검증한다.
- 직원 단일 클릭 시 직원이 하이라이트되고 소속 조직이 선택되며 확정 이벤트는 발생하지 않는지 컴포넌트 테스트로 검증한다.
- 더블클릭과 `[선택]` 버튼의 기존 확정 동작이 유지되는지 회귀 검증한다.

## 완료 조건

- 직원 단일 클릭 후 좌측 조직 선택과 스크롤 위치가 직원 소속 조직으로 이동한다.
- 하위 부서가 있는 모든 조직이 전무이사와 같은 아이콘을 표시한다.
- 5단계 이상 조직이 단계별로 계속 들여쓰기된다.
- 관련 단위 테스트, 타입 검사, ESLint, Stylelint가 통과한다.
