# 기능점수 산정 결과 보고 아티팩트 설계

- 작성일: 2026-08-17
- 대상: `C:\it\FP` 기능점수 산정 데이터
- 산출물: `FP/build-artifact.mjs` (생성기) + Artifact 도구로 게시하는 웹 페이지

## 1. 배경과 문제

`FP/` 에는 정통법(Detailed FP) 기준 산정 데이터가 5회차 누적되어 있다.

- 산정 명세: `fp-estimate-YYYY-MM-DD.csv` 5개 (2026-07-17 ~ 2026-08-09)
- 리포트: `reports/fp-estimate-report-YYYY-MM-DD.html` 5개 (`generate-report.mjs` 생성)

기존 HTML 리포트는 **실무 검증용**이다. 279행 전수 명세, CSV 재계산 불일치 목록,
고아 테이블 경고까지 담아 "산정이 정확한가"를 확인하는 문서다.

반면 경영진·발주처는 다른 질문을 한다 — **"규모가 얼마고 금액이 얼마인가, 그 근거는 믿을 만한가"**.
이 질문에 답하는 문서는 결론이 먼저 오고 근거가 뒤따라야 하며, 검증용 세부는 접히거나 빠져야 한다.

## 2. 목표와 비목표

**목표**

- 경영진·발주처가 스크롤 한 번으로 규모와 금액의 결론에 도달한다.
- 최신 산정본(2026-08-09)을 본문으로 하되, 5회차 규모 추이를 함께 보여 증가 흐름을 전달한다.
- 금액을 표시하되 보정계수가 대표 가정값이라는 사실을 오해 없이 전달한다.

**비목표**

- 279행 전수 명세 테이블은 넣지 않는다. 그것은 기존 `reports/` 의 역할이다.
- 기존 `generate-report.mjs` / `lib/render.mjs` 의 출력 형태는 건드리지 않는다.
- 필터·정렬 같은 탐색형 인터랙션은 넣지 않는다. 읽는 문서이지 찾는 도구가 아니다.

## 3. 생성 방식

손으로 HTML을 작성하지 않고 **`FP/build-artifact.mjs`** 를 새로 만든다.
FP.md Step 6의 "리포트는 손으로 작성하지 않고 반드시 생성기를 실행합니다" 원칙을 그대로 따른다.

```bash
node FP/build-artifact.mjs                    # 최신 CSV 기준
node FP/build-artifact.mjs --date=2026-08-09  # 특정 날짜 기준
```

- **입력**: `FP/fp-estimate-*.csv` 전체(추이용) + 지정 날짜 CSV(본문용) + 코드베이스 실측
- **출력**: `FP/artifact/fp-artifact-YYYY-MM-DD.html`
- **재사용**: `lib/csv.mjs`(파싱·검증), `lib/aggregate.mjs`(집계·재계산), `lib/scan.mjs`(실측),
  `lib/diff.mjs`(직전 대비 변경)를 그대로 import 한다. 새 산정 로직을 만들지 않는다.
- **보정계수·단가**: `generate-report.mjs` 의 `CONFIG` 와 **동일한 값**을 쓴다.
  두 곳에 같은 상수가 흩어지지 않도록 `lib/config.mjs` 로 추출하고 양쪽에서 import 한다.

집계 결과를 JSON으로 직렬화해 HTML `<script type="application/json">` 에 삽입하고,
페이지 스크립트가 이를 읽어 렌더링한다. CSV가 갱신되면 생성기 재실행만으로 아티팩트가 따라온다.

### 4.6 산정 근거

- 정통법 복잡도 매트릭스(데이터기능 RET×DET, 트랜잭션기능 FTR×DET)와 점수표.
- 보정계수 5종과 각각의 근거(`CONFIG.factors` 의 `basis`).
- 금액 산식 전개.
- **신뢰 근거**: CSV 기재값과 매트릭스 재계산값의 불일치 **0건**. 생성기가 CSV의 복잡도·점수를
  신뢰하지 않고 매번 재계산하므로 같은 입력이면 같은 결과가 나온다는 점을 함께 설명한다.

## 5. 시각화·스타일

- 외부 리소스를 쓰지 않는다. 아티팩트 CSP가 CDN·외부 폰트·원격 이미지를 차단한다.
  차트는 **인라인 SVG**로 직접 그린다.
- 차트: 유형별 구성(누적 바), 도메인별(가로 바), 추이(라인).
- `dataviz` 스킬의 팔레트 규칙을 따르고, 라이트/다크 양쪽에서 읽히도록 색 토큰을
  `:root` → `@media (prefers-color-scheme: dark)` → `:root[data-theme="dark"]` 순으로 정의한다.
- 표·차트는 `overflow-x: auto` 컨테이너 안에서만 가로 스크롤한다. 본문은 가로 스크롤이 없어야 한다.

## 6. 검증

- `node FP/build-artifact.mjs` 가 오류 없이 종료하고 HTML을 생성한다.
- 생성 HTML의 핵심 수치(UFP 1,309 / 보정 후 1,304.3 / 최종 1,032,995,779원)가
  `generate-report.mjs` 콘솔 출력과 일치한다.
- `lib/config.mjs` 추출 후 `node FP/generate-report.mjs --date=2026-08-09` 를 재실행해
  기존 리포트가 동일하게 재생성되는지 확인한다(회귀 방지).
- 아티팩트 게시 후 라이트/다크 렌더링과 가로 스크롤 부재를 확인한다.
