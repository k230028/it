# 예산 재신청·상세 접근 제어·정보화사업 카드 개선 설계

## 목표

결재가 완료된 정보화사업, 경상예산, 전산업무비를 새 이력 버전으로 재신청할 수 있게 하고, 승인된 최종본만 후속 예산 업무에 사용한다. 또한 예산 상세의 서버 접근 권한을 보강하고 정보화사업 카드의 조회·내보내기 기능을 확장한다.

## 범위와 용어

- 정보화사업은 `BPROJM`의 `ABUS_MNG_NO`와 `SNO` 버전 조합이다.
- 경상예산은 기존 plan 도메인의 예산번호와 순번 조합이다.
- 전산업무비는 `BCOSTM`의 `BG_NO`와 `BG_SNO` 버전 조합이다.
- 최종본은 `LST_YN='Y'`인 버전이며, 재신청 초안과 과거 이력은 `LST_YN='N'`이다.
- IT 조직은 `013`, `180`, `181`, `182`, `183`, `185`이다.

## 재신청 및 버전 전환

1. 작성부서의 사용자는 결재완료 건에 한해 `수정 후 재신청`을 요청할 수 있다. 결재중, 미결재, 반려, 타 부서 소유 건은 거부한다.
2. 서버는 원본의 부모 관리번호를 보존하고 동일 부모 키의 최대 순번에 1을 더한 새 버전을 생성한다. 원본의 본문, 하위 품목·상세, 담당자 스냅샷, 첨부 연결은 현재 신규 작성과 동일한 저장 규칙으로 복제·초기화한다.
3. 새 버전은 `LST_YN='N'`으로 생성한다. 따라서 목록·집계·후속 예산 처리는 승인 전 재신청 초안을 읽지 않는다.
4. 재신청 버전은 기존의 작성·저장·전자결재 신청 흐름을 사용한다. 승인 완료 이벤트는 결재 대상의 부모 키와 순번을 기준으로 같은 부모의 기존 `Y`를 `N`으로 바꾼 뒤 대상 버전을 `Y`로 바꾼다. 두 갱신은 단일 트랜잭션이다.
5. 완료 처리의 대상이 존재하지 않거나 이미 삭제되었거나 소유·결재 상태가 맞지 않으면 정상 완료로 숨기지 않고 안전하게 실패한다. 동일 완료 이벤트 재처리는 결과가 중복 전환되지 않도록 멱등성을 보장한다.

## API와 조회 계약

- 각 도메인은 현재 최종본 상세 조회와 별개로, 작성부서용 재신청 생성 API, 부모 번호 기준 이력 목록 API, 부모 번호와 순번 기준 이력 상세 API를 제공한다.
- 관리번호만 받는 기존 상세·목록·bulk 조회 API는 기본적으로 `LST_YN='Y'`만 반환한다. 이력 API와 결재 매핑 조회만 명시적 순번으로 과거/초안 레코드를 조회한다.
- 모든 도메인 쿼리 중 사업·예산을 업무 데이터로 소비하는 목록, 집계, 선택 목록, 대시보드, Excel 원본 조회를 점검해 `LST_YN='Y'` 조건을 DB 단계에 넣는다.
- DTO에는 이력 표시에 필요한 부모 번호, 순번, 최종 여부, 결재 상태, 등록·변경 시각을 포함한다. 생성된 OpenAPI 타입은 프론트에서 코드 생성으로 갱신한다.

## 상세 접근 권한

- `/api/projects/{id}`와 `/api/cost/{id}` 및 명시적 이력 상세 조회는 서비스 계층에서 데이터 범위를 검사한다.
- 허용자는 대상의 주관부서 코드와 같은 사용자, IT 조직 사용자, 시스템관리자다.
- 권한 없음은 프론트 라우트 여부와 무관하게 서버에서 거부한다. 이력 API와 재신청 API에도 동일한 소유권·역할 검사를 적용한다.

## 화면 설계

- 세 상세 화면의 사업명/예산명 오른쪽에 이력 아이콘을 둔다. 아이콘은 이력 다이얼로그를 열고, 이력 행을 선택하면 해당 순번의 읽기 전용 상세로 이동한다.
- 결재완료이면서 작성부서에 수정 권한이 있는 최종본에는 `수정 후 재신청` 버튼을 표시한다. 클릭하면 서버가 새 초안을 생성하고 해당 초안의 작성 화면으로 이동한다.
- 정보화사업 카드에서 IT 조직은 `부서 | 전체` 범위 토글을 사용할 수 있다. 확대 아이콘은 전체 화면 다이얼로그에 사업명, 주관부서명, IT 담당부서, 총 소요금액, 당해 요청예산, 자본예산 합계, 일반관리비 합계를 표로 표시한다.
- 카드의 Excel 버튼은 최종본만 대상으로 사업명, 시작일, 종료일, 주관부서명, 주관부서 담당팀장, 주관부서 담당자, IT담당부서, IT담당팀장, IT담당자, 총 소요금액, 당해 요청예산, 개발비, 기계장치, 기타무형자산, 자본예산 합계, 일반관리비 합계, 전결권을 내려받는다.
- `IT 담당부서` 체크박스는 로그인 사용자의 부서 코드가 사업의 IT 담당부서 코드와 일치하는 최종본만 필터링한다. 범위 선택과 함께 사용할 수 있다.

## 데이터베이스와 동시성

- 이미 존재하는 버전 키와 `LST_YN` 컬럼을 재사용한다. 새 Flyway 마이그레이션으로 도메인별 부모 키·최종 여부 조회와 동시 재신청의 순번 산정에 필요한 인덱스 또는 제약을 보강한다.
- 버전 생성은 부모 키에 대한 잠금 또는 원자적 순번 산정으로 같은 건의 동시 재신청에서 중복 순번이 생기지 않게 한다.
- 기존 적용 마이그레이션은 수정하지 않는다.

## 오류 처리

- 결재완료가 아닌 대상, 타 부서 대상, 존재하지 않는 대상, 새 버전 생성 경쟁 충돌은 공통 API 오류 계약에 맞는 명시적 오류로 응답한다.
- 프론트는 접근 거부, 최초 조회 실패, 빈 이력을 구분해 표시하며 접근 거부를 빈 화면으로 대체하지 않는다.

## 테스트와 검증

- 백엔드 단위·통합 테스트: 도메인별 버전 생성, 순번 증가, 결재 완료 전환, 기존 최종본 유지, 동시성/멱등성, 상세 권한 허용·거부, 최종본 필터를 검증한다.
- API/OpenAPI 계약 테스트: 신규 API와 DTO 필드를 검증하고 프론트 생성 타입을 갱신한다.
- 프론트 Vitest와 Playwright: 재신청 버튼 조건, 이력 다이얼로그와 선택 이동, IT 조직 범위 전환, IT 담당부서 필터, 확대 보기, Excel 호출, 접근 거부 화면을 검증한다.
- 완료 전 백엔드는 `./gradlew test`, `./gradlew check`, `./gradlew bootJar`; 프론트는 `npm run format:check`, `npm run check`, `npm test`, `npm run codegen:check`를 실행한다.
