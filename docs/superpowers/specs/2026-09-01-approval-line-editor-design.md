# 결재선 지정·수정 다이얼로그 설계

## 목적

`/budget/report`와 `/approval/list?tab=pending`에서 분산된 결재자 지정·추가·삭제·순서 변경을 하나의 직원 검색 기반 다이얼로그로 통합한다. 사용자는 조직도를 통해 직원을 찾고, 오른쪽 결재선에서 추가·삭제·순서 변경한 뒤 한 번의 적용으로 저장한다.

## 범위

- 두 화면에 `결재선 지정/수정` 진입 버튼을 제공한다.
- 공통 다이얼로그는 기존 `EmployeeSearchDialog`의 디자인과 조직도·부서원 조회·통합 검색·정렬·로딩·오류 처리를 재사용한다.
- 다이얼로그 오른쪽에 결재선 편집 패널을 제공한다.
- 결재중 신청서에서는 승인·반려 등 처리된 결재자를 읽기 전용으로 유지하고, 미결재 결재자만 변경한다.

## 사용자 흐름

1. 사용자가 `결재선 지정/수정`을 선택한다.
2. 다이얼로그 왼쪽의 조직도와 기존 직원 검색 영역에서 직원을 찾는다.
3. 선택한 직원을 오른쪽 결재선에 추가한다. 같은 사번은 중복 추가하지 않는다.
4. 결재선에서 직원을 삭제하거나 드래그 앤 드롭으로 순서를 조정한다.
5. `적용`을 누르면 변경을 반영하고, `취소` 또는 닫기는 원본을 유지한다.

## 프론트엔드 구조

### 공통 다이얼로그

- `EmployeeSearchDialog`는 기본 화면의 스타일·검색 동작·오류 처리를 보존한다.
- 공통 `ApprovalLineEditorDialog`는 직원 검색 영역과 결재선 편집 패널을 조합한다.
- 편집 패널의 항목은 사번, 성명, 직위, 부서와 편집 가능 여부를 가진다.
- 다이얼로그가 열릴 때 원본 결재선을 복제해 편집 상태를 만들고, 적용 성공 전에는 부모 상태나 서버 상태를 변경하지 않는다.
- 직원 추가 후에도 다이얼로그를 닫지 않는다. 선택한 직원이 이미 결재선에 있으면 중복 추가하지 않고 안내한다.

### 예산 보고서

- 기존의 개별 팀장·부서장·추가 결재자 조작 UI는 단일 진입 버튼과 현재 결재선 요약으로 대체한다.
- 적용 이벤트가 전달한 결재선을 화면 상태에 반영한 뒤 PDF 미리보기를 한 번만 다시 생성한다.
- 상신 전 결재선 검증과 서버 전송 순서는 현재 `ApprovalLine` 및 `getOrderedApprovalLineApproverIds` 계약을 유지한다.

### 결재 대기 목록

- 결재중 건의 타임라인에서 개별 결재자 변경·추가·삭제·정렬 제어를 제거하고 단일 `결재선 지정/수정` 버튼으로 대체한다.
- 권한이 있는 결재선 참여자 또는 관리자는 다이얼로그를 열 수 있다. 프론트엔드 표시는 UX 용도이며 서버가 권한을 최종 판정한다.
- 처리된 결재자는 고정된 항목으로 표시한다. 미결재 결재자만 추가·삭제·교체·정렬할 수 있다.
- 적용 성공 뒤 최신 결재선으로 타임라인과 목록을 다시 조회한다.

## 서버 API와 트랜잭션

- 기존 단건 변경·추가·삭제·정렬 API는 호환성을 위해 유지한다.
- 새 일괄 결재선 변경 API는 신청서 관리번호와 최종 미결재 결재자 사번 순서를 입력으로 받는다.
- 서비스는 하나의 쓰기 트랜잭션에서 다음을 수행한다.
  1. 신청서와 현재 결재선을 조회하고 권한을 확인한다.
  2. 처리된 결재자가 입력에 의해 변경되지 않았는지 확인한다.
  3. 입력 사번의 공백·중복·직원 존재 여부를 검증한다.
  4. 미결재 결재자만 입력 순서로 교체·추가·삭제한다.
  5. 최종 결재 순번을 일관되게 저장하고 최신 결재선을 반환한다.
- 검증 또는 저장이 실패하면 트랜잭션 전체를 롤백한다. 프론트엔드는 편집 상태를 유지해 사용자가 수정하거나 재시도할 수 있게 한다.
- 결재자 조회 응답에는 사번 외에 성명·직위·부서 표시 정보를 포함한다. 목록·상세 조회는 배치 조회 또는 조인으로 보강해 결재자 수만큼 사용자 조회를 반복하지 않는다.
- 전자결재 상태 변경이므로 새 일괄 API에도 기존 MFA 요구 사항을 적용한다.

## 오류 처리

- 직원·조직 검색 오류는 기존 `EmployeeSearchDialog`의 공통 오류 안내를 사용한다.
- 중복 추가, 빈 결재선 등 클라이언트에서 확정할 수 있는 오류는 적용 전 차단한다.
- 서버 권한·상태 경합·직원 비활성 또는 누락 오류는 공통 API 오류 매핑으로 표시한다.
- 적용 성공 전 다이얼로그를 닫지 않으며, 실패 시 원본과 편집 상태가 섞이지 않게 한다.

## 테스트

- 프론트 단위 테스트: 편집 상태 복제와 취소, 중복 차단, 추가·삭제·정렬, 처리된 결재자 고정, 적용 이벤트를 검증한다.
- 프론트 E2E: 조직도 선택부터 직원 추가·정렬·적용까지의 예산 보고서와 결재 대기 목록 흐름을 검증한다.
- 백엔드 단위·MVC 테스트: 일괄 API의 권한, 입력 검증, 처리 완료 결재자 보호, 순서 저장, 롤백을 검증한다.
- API 계약 변경 뒤 OpenAPI 생성 타입을 갱신하고 `codegen:check`를 통과시킨다.

## 비범위

- 다른 신청서 양식과 협의회 결재선 UI의 일괄 전환은 포함하지 않는다.
- 기존 직원 검색의 검색 조건·조직 데이터 모델·권한 정책 자체는 변경하지 않는다.
