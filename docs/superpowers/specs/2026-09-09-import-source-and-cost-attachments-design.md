# 반입 원본 분리 및 전산업무비 첨부파일 설계

## 1. 목적

편성요청서 일괄업로드로 생성된 수기등록(`IT_PTL_APF_PRG_STS_C=9`, 레거시 `09` 포함) 정보화사업·경상사업의 반입 원본을 일반 첨부파일 목록과 분리한다. 일반 첨부파일 목록에는 사용자가 해당 업무에 직접 첨부한 파일만 표시하고, 반입 원본은 제목 옆 아이콘을 통해 전용 `[반입 원본 파일]` 다이얼로그에서 조회한다.

전산업무비에도 같은 조회 구조와 일반 첨부파일 편집 기능을 추가한다. 목록 화면의 인라인 작성·수정에서는 첨부를 받지 않고, 저장된 전산업무비의 개별 수정 경로에서만 파일을 추가·삭제할 수 있게 한다.

## 2. 확정된 업무 규칙

- 수기등록 상태의 기준 코드는 `9`이며 기존 데이터 호환을 위해 `09`도 동일하게 판정한다.
- 수기등록 항목은 재상신되지 않는다. 이 기능은 수기등록 항목에 재상신 경로를 새로 만들지 않는다.
- 전산업무비 일반 첨부파일은 `costBgNo`에 연결한다. 새 개정 순번이 생겨도 같은 관리번호의 모든 순번이 첨부파일을 공유한다.
- 정보화사업과 경상사업은 기존과 같이 `abusMngNo`에 직접 연결된 일반 첨부파일을 공유한다.
- 반입 원본은 기존 계약을 유지한다. 파일 종류는 `편성요청서반입`, 부모 식별자는 `apfMngNo`이다.
- 반입 원본은 조회와 다운로드만 허용하며 범용 파일 API로 추가·변경·삭제할 수 없다.
- 일반 첨부파일 건수에는 반입 원본을 포함하지 않는다.

## 3. 선택한 접근

반입 원본 표시와 다운로드 책임을 전용 공통 다이얼로그로 분리한다. 기존 `ApplicationViewerDialog`의 반입 원본 분기와 정보화사업·경상사업·전산업무비 상세가 같은 조회·선택·다운로드 구현을 재사용한다.

기존 `ApplicationViewerDialog`를 그대로 상세 화면에서 호출하는 방식은 PDF 미리보기 책임과 원본 파일 책임을 계속 결합하고, 신청서를 불필요하게 한 번 더 조회한다. 일반 첨부 목록을 다이얼로그 안에 다시 구현하는 방식은 폴더 구조와 ZIP 다운로드 동작을 중복시킨다. 따라서 전용 다이얼로그와 공통 상태 로직을 분리하는 방식을 사용한다.

## 4. 화면 설계

### 4.1 공통 첨부파일 목록

`AttachmentListSection`의 제목 영역에 명명된 헤더 액션 슬롯을 추가한다. 기존 호출부에는 시각적 변화가 없으며, 필요한 화면만 슬롯에 반입 원본 아이콘 버튼을 전달한다.

아이콘 버튼은 다음 조건을 모두 만족할 때 표시한다.

- 항목이 수기등록 상태이다.
- 신청서관리번호 `apfMngNo`가 존재한다.

아이콘에는 `[반입 원본 파일]` 툴팁과 동일한 접근성 이름을 제공한다. 클릭하면 해당 `apfMngNo`를 대상으로 전용 다이얼로그를 연다. 원본 파일의 존재 여부는 다이얼로그가 열린 뒤 서버 응답으로 판정하므로, 수기등록 항목은 원본이 없더라도 아이콘을 유지하고 명시적인 빈 상태를 보여 준다.

### 4.2 정보화사업·경상사업 상세

현재 `AttachmentListSection`에 함께 전달하는 두 그룹을 분리한다.

- 본문 목록: `APG_FL_KD_NM=정보화사업`, 부모 `abusMngNo`인 파일만 전달한다.
- 반입 원본: 목록에 전달하지 않고 제목 옆 아이콘으로만 접근한다.

이에 따라 사업에 직접 첨부한 파일이 없으면 목록 본문은 빈 상태를 표시하더라도, 수기등록 항목의 반입 원본 아이콘은 독립적으로 사용할 수 있다.

### 4.3 전산업무비 상세

일반 전산업무비 상세와 금융정보단말기 상세 모두 조회용 `AttachmentListSection`을 추가한다.

- 본문 목록: `APG_FL_KD_NM=전산업무비`, 부모 `costBgNo`인 파일
- 반입 원본: 수기등록이고 `apfMngNo`가 있을 때 제목 옆 아이콘

일반 전산업무비의 목차에는 첨부파일 항목을 추가한다. 금융정보단말기 상세에는 기존 본문 흐름 아래 독립 카드로 배치한다.

### 4.4 전산업무비 개별 수정

다음 경로에만 `AttachmentUploadField`를 제공한다.

- `/info/cost/form?id=...` 단건 수정 화면
- 금융정보단말기 개별 상세에서 연 수정 다이얼로그

다음 경로에는 첨부 UI와 첨부 저장 동작을 제공하지 않는다.

- 전산업무비 목록의 인라인 작성·수정
- 목록에서 연 금융정보단말기 다이얼로그
- 신규·복수 행 전산업무비 작성 화면
- 부모 전산업무비에서 금융정보단말기를 새로 만드는 연결 신규 모드

금융정보단말기 다이얼로그는 호출부가 `개별 상세에서 연 기존 항목 수정`임을 명시적으로 전달받을 때만 첨부 영역을 활성화한다. 관리번호 존재 여부만으로 판정하면 목록에서 기존 항목을 편집할 때도 첨부 UI가 노출되므로 호출 경로 플래그를 별도로 둔다.

## 5. 프론트엔드 구성

### 5.1 반입 원본 공통 기능

- `RequestFormSourceFilesDialog`: `v-model:visible`과 `apfMngNo`를 받는 전용 다이얼로그
- 반입 원본 상태 로직: 열릴 때 파일 조회, 이전 요청 무효화, 선택 초기화, 전체·선택 ZIP 다운로드, 재시도와 오류 상태 관리
- `RequestFormSourceFiles`: 기존 폴더 트리와 파일 선택 표시를 유지하되 단건 다운로드도 `useAttachmentDownload()`를 사용
- `ApplicationViewerDialog`: 수기등록 분기에서 위 공통 상태·표시 구현을 사용하고 일반 신청서 PDF 책임만 자체적으로 유지

다이얼로그는 열릴 때만 원본 목록을 조회한다. `apfMngNo`가 바뀌거나 닫힌 뒤 완료된 이전 요청이 현재 상태를 덮지 않도록 요청 세대를 비교한다.

### 5.2 사업 상세 상태

`useProjectDetailPage`는 사업 직접 첨부 목록만 상세 컴포넌트에 전달한다. 기존 `useProjectRequestFormFiles` 기반 원본 그룹과 그룹별 재시도 분기는 제거하고, 수기등록 여부와 `apfMngNo`를 반입 원본 아이콘·다이얼로그에 전달한다.

수기등록 판정은 기존 `isManualRegistration()`을 재사용하여 상태 코드 해석을 중복하지 않는다.

### 5.3 전산업무비 첨부 상태

사업 첨부 편집 패턴과 같은 책임을 가진 전산업무비 전용 composable을 둔다.

- 파일 종류 상수 `전산업무비`
- `costBgNo`별 기존 파일 조회와 재조회 실패 가드
- 신규 파일 선택 상태
- 기존 파일 삭제 예약 상태
- 본문 저장 성공 뒤 삭제와 업로드를 반영하는 동기화 함수
- 일부 업로드 실패 시 실패 파일만 선택 상태에 보존

조회 화면과 수정 화면은 같은 목록 조회 함수를 사용한다. 목록 화면의 인라인 편집 흐름은 이 composable을 생성하거나 호출하지 않는다.

## 6. 저장 흐름

### 6.1 일반 전산업무비 단건 수정

1. 수정 화면 진입 시 `costBgNo` 기준 기존 첨부 목록을 조회한다.
2. 사용자가 고른 신규 파일과 삭제 예약은 화면 상태로만 보관한다.
3. 자동 임시저장은 전산업무비 본문만 저장한다. 파일은 업로드하거나 삭제하지 않는다.
4. 사용자가 `[저장]`을 실행하면 전산업무비 본문을 먼저 저장한다.
5. `409 COST_SOURCE_CHANGED`가 발생하면 첨부 상태를 유지하고 파일 처리를 보류한다.
6. 사용자가 충돌 해결 값을 선택하고 최신 스탬프로 본문 재저장에 성공하면 첨부 동기화를 시작한다.
7. 본문 저장과 첨부 동기화가 모두 끝난 뒤에만 전체 저장 성공 흐름으로 이동한다.

### 6.2 금융정보단말기 개별 수정

개별 상세에서 연 수정 다이얼로그도 본문 저장 성공 뒤 동일한 첨부 동기화를 수행한다. 목록·연결 신규·로컬 모드는 첨부 상태를 만들지 않고 현재 저장 동작을 유지한다.

### 6.3 부분 실패

본문 저장 성공 뒤 첨부 동기화가 실패해도 본문을 되돌리지 않는다. 사용자에게 `본문은 저장되었지만 첨부파일 반영에 실패했다`는 부분 성공 상태를 명확히 알리고 화면을 유지한다.

- 삭제 실패: 이후 업로드를 중단하고 삭제 예약과 신규 파일 선택을 유지한다.
- 다건 업로드 일부 실패: 성공 파일은 목록에 반영하고 실패 파일만 선택 상태에 남긴다.
- 첨부 목록 재조회 실패: 이전 목록을 새 성공처럼 표시하지 않고 재시도 가능한 오류를 표시한다.

재시도 시 본문 저장을 다시 수행한 뒤 최신 동시성 스탬프가 확인된 경우에만 첨부를 다시 반영한다. 이 규칙은 첨부만 별도로 변경하면서 본문 수정 권한이나 동시성 확인을 우회하는 경로를 만들지 않는다.

## 7. 백엔드 파일 권한

새 파일 종류 `전산업무비`를 파일 종류 레지스트리에 등록한다. DB 테이블과 컬럼은 공통 첨부파일 테이블을 그대로 사용하므로 DDL 변경은 없다.

### 7.1 읽기 판정기

부모 `costBgNo`의 미삭제 최종 전산업무비가 존재해야 한다.

- 관리자: 허용
- 담당부서가 인증 사용자의 부점과 같음: 허용
- 미인증, 부모 없음, 다른 부서, 삭제된 부모: 거부

이는 전산업무비 상세 API의 데이터 범위와 일치한다. 같은 관리번호의 개정 순번은 파일을 공유하므로 읽기 판정도 현재 최종본을 기준으로 한다.

### 7.2 대상 쓰기 판정기

부모 `costBgNo`의 미삭제 최종 전산업무비가 존재하고 본문 수정과 같은 소유권 규칙을 만족해야 업로드를 허용한다.

- 관리자
- 최초 작성자
- 담당부서가 같은 사용자

범용 파일 API의 기존 행 삭제를 허용하되, 현재 공통 계약에 따라 파일 업로더 또는 관리자만 삭제할 수 있다. 반입 원본 종류는 계속 `allowsGenericMutation=false`를 유지한다.

### 7.3 저장 경로

`FileStoragePathPolicy`에 `전산업무비` 종류의 안전한 서버 경로 별칭을 등록한다. 클라이언트가 전달한 부모·종류 값은 기존 허용문자 검증과 기준 디렉터리 포함 검증을 그대로 통과해야 한다.

## 8. 오류 및 빈 상태

- 반입 원본 로딩: 다이얼로그 내부 스피너
- 반입 원본 조회 실패: 다이얼로그 내부 오류와 `[다시 시도]`
- 반입 원본 없음: 권한 오류나 정상 파일과 혼동하지 않는 빈 상태 문구
- 단건·ZIP 다운로드 실패: 서버 메시지를 직접 노출하지 않고 번역된 오류 Toast
- 일반 첨부 목록 최초 조회 실패: 정상 빈 목록으로 숨기지 않고 오류 배너
- 일반 첨부 재조회 실패: 이전 성공 목록을 새 성공으로 간주하지 않고 재시도 제공
- 파일 업로드 부분 실패: 실패 파일명과 재시도 안내
- 부모 관리번호 누락: 업로드를 호출하지 않고 사용자용 오류로 차단

## 9. 테스트 전략

### 9.1 백엔드

- `전산업무비` 읽기 판정기의 관리자·같은 부서·다른 부서·부모 없음·삭제 부모 테스트
- 대상 쓰기 판정기의 관리자·작성자·같은 부서·무권한 테스트
- 파일 종류 레지스트리 중복 및 등록 계약 테스트
- 업로드 대상 부모 검증과 미등록 종류 차단 테스트
- 전산업무비 첨부 목록·다운로드 권한 통합 테스트
- 반입 원본의 범용 수정·삭제 차단 회귀 테스트
- 저장 경로 별칭과 경로 안전성 테스트

### 9.2 프론트엔드 단위 테스트

- `AttachmentListSection` 헤더 액션 슬롯의 기본 비노출과 전달 렌더링
- 반입 원본 다이얼로그의 지연 조회, 요청 전환, 빈 상태, 오류·재시도, 선택·전체 다운로드
- `RequestFormSourceFiles` 단건 인증 다운로드
- 정보화사업·경상사업 상세에서 반입 원본이 일반 목록과 건수에서 제외되는지 확인
- 수기등록 `9`·`09`에서만 원본 아이콘이 표시되는지 확인
- 일반·금융정보단말기 전산업무비 상세의 첨부 목록과 원본 아이콘 확인
- 전산업무비 단건 수정의 선택·삭제 예약·부분 실패 유지
- 자동저장과 충돌 대기 중 첨부 API가 호출되지 않는지 확인
- 충돌 해결 저장 성공 뒤 첨부가 한 번만 동기화되는지 확인
- 목록·신규·복수·연결 신규 모드에 첨부 입력이 없는지 확인
- 금융정보단말기 개별 상세 진입에서만 수정 다이얼로그 첨부 입력이 표시되는지 확인

### 9.3 사용자 흐름 테스트

- 일괄 반입 정보화사업·경상사업에서 일반 첨부 목록과 반입 원본 다이얼로그 분리
- 수기등록 전산업무비의 반입 원본 조회와 다운로드
- 일반 전산업무비 단건 수정 후 첨부 추가·삭제
- 금융정보단말기 개별 상세 수정 후 첨부 추가
- 목록 화면 작성·수정에서 첨부 기능이 노출되지 않음
- 전산업무비 개정 순번을 바꿔 조회해도 같은 일반 첨부 목록이 표시됨

## 10. 문서 및 계약 동기화

- 프론트 공통 컴포넌트 가이드에서 `AttachmentListSection`의 헤더 액션 슬롯과 반입 원본 분리 사용법을 갱신한다.
- 백엔드 파일 보안 가이드의 종류별 읽기·쓰기 표에 `전산업무비`를 추가한다.
- 새 API DTO나 엔드포인트는 만들지 않는다. 기존 범용 파일 API를 사용하므로 OpenAPI 생성 타입 변경은 예상하지 않지만 `codegen:check`로 확인한다.

## 11. 범위 제외

- 수기등록 항목의 재상신 기능
- 목록 화면에서의 첨부 추가·삭제
- 신규 전산업무비가 저장되기 전 파일 임시 업로드
- 반입 원본 파일의 수정·삭제·재업로드
- 기존 첨부파일을 개정 순번별로 분리하는 데이터 이관
- 공통 첨부파일 테이블의 물리 구조 변경
