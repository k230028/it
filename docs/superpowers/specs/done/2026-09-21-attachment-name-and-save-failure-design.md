# FE-93 첨부 파일명과 저장 실패 처리

- 파일명은 확장자 포함 UTF-8 100바이트. 기존 textLength 계산 재사용. DB 변경 없음.
- 공통 첨부 선택에서 초과 파일이 하나라도 있으면 선택 묶음 미추가, 인라인 오류와 기존 선택 유지.
- 사업·비용 본문 저장 전 및 첨부 삭제 전 검사.
- 사업 첨부 실패는 본문 저장 사실을 확인 다이얼로그로 알리고 완료·이동 중단.
- 실패 파일과 생성된 관리번호·스탬프를 유지하여 같은 사업으로 재시도.
- 정상·병합 저장의 첨부 후처리 공통 적용. 본문 자동 롤백 없음.
- 서버 직접 호출은 기존 서버·DB 검증 유지. 프론트 수정만 수행.

## FE-93 추가 적용: 본문 에디터 파일명 사전 검사 (2026-09-21)

- 사업 가이드와 요구사항정의서 작성·수정의 서버 업로드형 에디터에 확장자 포함 UTF-8 100바이트 검사를 추가했다.
- 파일 선택, 이미지 선택, 이미지 붙여넣기·드래그 경로에서 공통 검사 함수를 사용한다. 초과하면 구체적인 파일명 안내를 표시하고 업로드 콜백을 호출하지 않는다.
- 파일 선택 입력값을 초기화하여 재선택할 수 있고, 다이얼로그를 유지한다. 붙여넣기·드래그는 임시 이미지 노드를 만들기 전에 거부한다.
- Base64 본문 이미지와 엑셀 내용 일괄 입력은 파일 테이블 저장 경로가 아니므로 이 검사를 적용하지 않는다.

- 이번 추가분 증적: it_frontend/.cache/editor-name-{check,format,unit,e2e}.log. 실DB 업로드 시험은 미실시.

- 추가분 최종 검증: 전체 단위 538파일·6,092건 통과, 관련 브라우저 1건 통과, npm run check 및 format:check 종료코드 0. 기존 PDF는 추가분 반영 전 산출물이며 이번 기록은 Markdown에 반영함.


## FE-93 추가: 파일명 초과 바이트 안내 (2026-09-21)

- 오류 문구를 `현재 N바이트 / 최대 100바이트 — M바이트 초과`, `파일명이 너무 깁니다. 파일명을 줄인 뒤 다시 선택해 주세요.`, `파일: 원본파일명`의 세 줄로 변경했다.
- 확장자를 포함한 기존 UTF-8 계산값을 사용하며 초과량은 현재 길이에서 100을 뺀 값이다. 여러 파일이 초과하면 파일별로 안내한다.
- 공통 첨부 영역과 본문 에디터 알림에 줄바꿈을 유지한다. 기존 선택 거부 및 업로드 차단 동작은 유지한다.
- 관련 단위 테스트 38건, 브라우저 테스트 2건 통과. 변경 파일 ESLint 및 Prettier 검사 통과.
- 증적: it_frontend/.cache/filename-byte-message-tests.log, it_frontend/.cache/filename-byte-message-e2e.log. 로컬 반영이며 기존 배포 ZIP/WAR는 갱신하지 않았다.
