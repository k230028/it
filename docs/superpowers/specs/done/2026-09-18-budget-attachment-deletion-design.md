# BE-115 예산 첨부파일 삭제 권한 설계

## 요청과 범위

- 정보화사업·경상사업·전산업무비·금융단말 첨부의 본인·동일 부서·시스템관리자 삭제 허용.
- 동일 부서는 기존 예산 수정 권한처럼 활성 최종 원장의 주관부서와 로그인 부서가 같은 경우로 판정.
- 금융단말 상세 수정 다이얼로그의 첨부는 전산업무비 종류를 사용하므로 포함.
- DB 및 API 요청·응답 필드 변경 없음. 다른 게시판·문서의 삭제 권한은 유지.

## 구현 계약

- 기존 파일 종류·부모 키를 서버에서 읽고 권한 판정. 클라이언트 부서값 미사용.
- 본인 업로드 또는 시스템관리자 허용. 타인 업로드 파일은 주관부서 일치 시 허용.
- 예산 종류의 부서 예외는 삭제에만 적용. PUT 파일 연결 변경 권한은 확대하지 않음.
- 정보화사업 종류의 범용 삭제 차단을 분리 해제. 반입 원본·배너·사용자가이드 보호 유지.
- 단건·일괄 삭제에 동일 부서 기준 적용. 일괄 삭제의 부모 조회는 1회 이하.
- 예산 본문의 결재 상태·기간·동시성 검사는 기존 계약 유지.
- 첨부의 부모 키에 개정 순번이 없어 기존 첨부 API처럼 활성 최종본 기준 판정.

## 검증과 산출물

- 실제 Controller→권한 검사→FileService 조합으로 본인·동료·관리자·타부서 검증.
- 부모 누락·부서 누락·다른 파일 종류·메타데이터 변경 차단·일괄 원자성 회귀 검증.
- 네 업무 화면의 기존 첨부 삭제→신규 업로드→재조회 Playwright 검증.
- 분석/설계서, 테스트 결과서, 실행 증적, PDF 작성. 실제 운영 데이터 검증은 별도 표시.
