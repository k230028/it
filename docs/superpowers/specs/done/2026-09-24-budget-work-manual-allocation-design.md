# 예산 작업 비목별 편성 결과 수기 입력 설계

- 작성일: 2026-09-24
- 대상 화면: `/budget/work` [비목별 편성 결과]
- 관련 API: `GET /api/budget/work/summary`, 신규 `PUT /api/budget/work/manual-allocations`

## 1. 목적

원천 데이터(결재완료 정보화사업·경상사업·전산업무비)가 없거나 부족한 과거 연도(2026 이하)의 비목별 요청·편성 금액을
시스템관리자가 직접 입력해, 예산 작업·정보기술부문 예산 조회/비교와 다음 연도 화면의 전년 비교 열에 반영한다.

## 2. 요구사항

| 번호 | 내용 |
| --- | --- |
| R1 | 2026 이하 연도에서만 [수정] 버튼을 표시하고, 편집 모드에서 [취소]·[저장]을 표시한다. |
| R2 | 편집 모드에서 요청금액과 편성금액 열 사이에 `편성률` 열을 추가해 세부 비목별 편성률을 입력받는다. |
| R3 | 입력값은 당해 연도 **편성률**과 **편성금액**이며, 요청금액은 `편성금액 × 100 ÷ 편성률`(원 단위 반올림)로 계산한다. |
| R4 | 소계·합계·증감율은 입력 즉시 재계산된다. |
| R5 | 2027 이후 연도는 어떤 경로로도 수정할 수 없다(화면 비노출 + 서버 거부, 연도가 지나도 고정). |
| R6 | 물리 스키마는 변경하지 않는다. 기존 `TPRMPP_BBUGTM`의 `BG_DUP_AMT`·`ASG_RT`만 사용한다. |
| R7 | 표시 규칙은 연도와 무관하게 `BBUGTM` 기준으로 동일하다. 수기 행이 있는 비목은 수기 값이 계산값을 대체하고, 없는 비목은 기존 계산값을 쓴다. |

## 3. 데이터 모델

`TPRMPP_BBUGTM`에 비목당 1행의 수기 행을 둔다.

| 컬럼 | 값 |
| --- | --- |
| `BG_NO`, `SNO` | 기존 채번(`BG-{연도}-{seq}`), 순번 1 |
| `BSE_YY` | 예산연도 |
| `FNT_TB_NM` | `MANUAL` |
| `PK_COL_NM` | 비목코드(`IOE_C`와 동일) |
| `FNT_TB_CRY_SNO` | 0 |
| `IOE_C` | 비목코드 |
| `BG_DUP_AMT` | 편성금액(원) |
| `ASG_RT` | 편성률(0 초과 999.99999 이하, 소수 5자리) |
| `DEL_YN` | 저장 시 `N`, 입력 해제 시 `Y` |

요청금액은 저장하지 않고 조회 시 `BG_DUP_AMT × 100 ÷ ASG_RT`로 계산한다.

## 4. 서버

### 4.1 저장 API

`PUT /api/budget/work/manual-allocations` (컨트롤러 클래스 수준 `hasRole('ADMIN')`)

```json
{ "bgYy": "2026", "items": [{ "ioeC": "101", "dupRt": 80, "dupAmount": 8000000 }] }
```

- 요청의 `items`가 해당 연도의 수기 입력 전체 상태다. 목록에 없는 비목의 기존 수기 행은 soft delete한다.
- 검증 실패는 `CustomGeneralException`(400)으로 거부한다.
  - `bgYy`가 4자리 숫자가 아니거나 2026 초과
  - `ioeC`가 공통코드 `IOE`에 없거나 중복
  - `dupRt`가 null·0 이하·999.99999 초과, `dupAmount`가 null·음수
- 응답은 저장 직후 `SummaryResponse`.

### 4.2 조회 규칙 (`BudgetSummaryService.getSummary`)

- `BBUGTM` 읽기 결과를 `MANUAL` 행과 원천 행으로 나누고, 결재완료 원천 필터는 원천 행에만 적용한다.
- 표시 행(동일 표시명 비목 묶음)에 수기 행이 하나라도 있으면 그 묶음의 요청·편성금액은 수기 값 합계로 대체하고 `manual=true`를 응답한다.
- `SummaryItem`에 `manual`(boolean, 필수) 필드를 추가한다.

### 4.3 정보기술부문 예산 조회·비교 반영 (`ItBudgetQueryRepositoryImpl.findSummary`)

- 수기 편성은 비목 단위 입력이라 정보기술·정보보호 구분이 없으므로 **모두 정보기술부문**으로 반영한다.
- 수기 행이 있는 비목은 원천(BITEMM·BCOSTM) 집계 대신 수기 값으로 대체한다: 정보기술 편성액 = Σ수기 편성금액,
  정보기술 요청액 = Σ(편성금액 × 100 ÷ 편성률), 정보보호 요청·편성액 = 0.
- 조회 화면의 '편성'과 비교 화면의 금년·전년 금액은 편성액(`*AdjAmt`) 기준이다.
- 대체 판정은 비목코드(IOE_C) 단위다. 예산 작업 요약은 같은 표시명 비목을 한 행으로 묶어 대체하므로, 표시명이 같은 서로 다른
  비목코드에 원천 편성과 수기 편성이 나뉘어 있으면 두 화면 합계가 다를 수 있다.
- 판정 규칙(`BudgetManualAllocationPolicy`)은 두 도메인이 함께 쓰므로 `work.entity` 패키지에 둔다(레이어 방향 유지).

### 4.4 수기 행 보호

- `apply-items`의 연도 전체 soft delete(`softDeleteByBseYy`)는 `MANUAL` 행을 제외한다.
- 사업별 편성 결과·편성비목 목록 등 원천 기준 조회는 `MANUAL` 행을 제외한다.

## 5. 화면

- 페이지는 관리자 전용이므로 역할 판정 없이 연도(≤ 2026)로만 [수정] 버튼을 노출한다.
- 편집 상태·초안·요청금액 계산·저장 요청 조립은 `composables/budget/useBudgetManualAllocation.ts`가 담당하고,
  초안을 반영한 `SummaryResponse`를 기존 `useBudgetSummaryRows`에 넣어 소계·합계·증감율을 재사용한다.
- 편성금액 입력은 현재 선택 금액 단위로 받고 원으로 환산해 전송한다.
- 편성률과 편성금액 중 하나만 입력한 비목은 저장을 막고 안내한다. 둘 다 비우면 수기 입력 해제로 본다.
- 수기 값 비목에는 `수기` 표시를 붙인다.
- 백엔드 DTO 변경 후 `npm run codegen`으로 `app/types/api.d.ts`를 재생성한다.

## 6. 검증

- 서버: 수기 저장 서비스 단위 테스트(연도 제한·검증·대체·해제), 요약 대체 규칙 단위 테스트, 수기 행 보호 Oracle 통합 테스트.
- 화면: 수기 입력 composable 단위 테스트(요청금액 계산·합계 반영·요청 조립·부분 입력 차단).
- 브라우저: 2026 편집·저장·재조회, 2027 [수정] 미노출, 2027 화면 전년(2026) 열 반영.
