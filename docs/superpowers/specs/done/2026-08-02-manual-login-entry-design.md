# 수동 로그인 진입 정책 설계

## 목표

`/login`을 항상 수동 로그인 화면으로 사용한다. 인증된 사용자가 `/login`에 접근하면 기존 세션을 종료한 뒤 수동 로그인 폼을 표시하고, 미인증 사용자가 보호된 업무 경로에 접근할 때만 기존 SSO 자동 진입을 유지한다.

## 동작 계약

- 로그아웃 버튼을 누르면 서버 로그아웃과 클라이언트 인증 상태 정리를 수행한 뒤 `/login`으로 이동한다.
- 미인증 사용자가 `/login` 또는 `/login?next=<내부 경로>`에 접근하면 SSO를 시작하지 않고 수동 로그인 폼을 표시한다.
- 인증된 사용자가 `/login`에 접근하면 `logout()`을 한 번 수행하고 같은 로그인 경로에서 수동 로그인 폼을 표시한다.
- 수동 로그인 성공 후 `next`가 안전한 내부 경로이면 해당 경로로 이동하고, 없거나 안전하지 않으면 `/`로 이동한다.
- `error=sso`가 있으면 기존 SSO 실패 안내를 로그인 폼 위에 표시한다.
- 미인증 사용자가 `/login` 이외의 보호 경로에 접근하면 원래 경로를 `next`로 보존해 기존 SSO 진입을 수행한다.

## 구현 구조

### 전역 클라이언트 인증 미들웨어

`app/middleware/auth.global.ts`에서 로그인 경로를 일반 보호 경로보다 먼저 처리한다. 로그인 경로에서는 `redirect`나 `next` 유무와 관계없이 SSO 이동을 하지 않는다. 세션 복원 후 인증 상태라면 `logout()`을 호출하고, 미인증 상태가 된 것을 확인한 뒤 라우팅을 계속한다.

로그인 경로가 아닌 보호 경로의 세션 복원 및 SSO 이동 로직은 유지한다.

### Nitro 서버 미들웨어

`server/middleware/sso-auth-redirect.ts`는 모든 canonical 로그인 경로를 SSO 리다이렉트 대상에서 제외한다. 서버 미들웨어는 httpOnly 인증 쿠키를 직접 폐기하지 않으며, 인증된 사용자의 실제 로그아웃은 Vue 애플리케이션이 시작된 뒤 전역 인증 미들웨어가 담당한다.

### 로그인 페이지

`app/pages/login.vue`에서 SSO 자동 이동 상태와 `window.location.replace()` 호출을 제거한다. 페이지는 마운트 직후 수동 로그인 폼을 표시한다. 기존 입력 검증, 오류 표시, `error=sso` 안내, 안전한 `next` 복귀 로직은 유지한다.

## 오류 처리

`logout()`은 현재 store 계약대로 서버 요청 실패 여부와 관계없이 클라이언트 인증 상태를 정리한다. 따라서 인증된 사용자의 `/login` 진입은 로그아웃 API 장애가 있어도 수동 로그인 폼을 표시할 수 있다. 수동 로그인 실패는 기존 화면 오류 메시지로 알린다.

## 테스트

- 전역 인증 미들웨어 단위 테스트로 미인증 `/login?next=...`가 SSO를 시작하지 않는지 검증한다.
- 전역 인증 미들웨어 단위 테스트로 인증된 `/login` 접근이 `logout()`을 호출하고 홈으로 되돌리지 않는지 검증한다.
- Nitro 서버 미들웨어 단위 테스트로 `/login`, `/LOGIN`, 쿼리가 있는 로그인 경로가 모두 SSO 리다이렉트 없이 통과하는지 검증한다.
- 로그인 페이지 또는 정적 인증 E2E 테스트로 `/login` 직접 접근 시 수동 로그인 폼이 표시되고 SSO 요청이 발생하지 않는지 검증한다.
- 보호 경로 직접 접근의 기존 SSO 테스트를 유지해 자동 SSO 범위가 축소되지 않았는지 확인한다.

## 제외 범위

- SSO 백엔드 엔드포인트와 인증 쿠키 발급 정책은 변경하지 않는다.
- 수동 로그인 API와 로그인 폼의 필드 및 디자인은 변경하지 않는다.
- 보호 경로의 자동 SSO 정책은 변경하지 않는다.
