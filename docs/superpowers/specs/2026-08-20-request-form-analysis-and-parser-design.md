# 편성요청서 분석 진행·파일 진단·파서 보강 설계

## 목적

편성요청서 폴더 업로드의 분석 진행 상태를 명확히 보여주고, 분석 결과 화면의 파일·진단 정보를 폴더 중심으로 정리한다. 동시에 실제 2026년 IT인프라 자원증설 요청서에서 발생하는 파싱 예외를 회귀 테스트로 재현해 경상사업 1건 양식을 정상 처리하고, 파일명·전결권자 해석 규칙을 보강한다.

## 범위

### 포함

- 폴더 업로드 dry-run에 전용 `[편성요청서 분석]` 진행 다이얼로그 적용
- 기존 `[편성요청서 반영]` 진행 다이얼로그와 시각·상태 계약 공유
- 파일명에 `요청서`가 포함된 `.xls`·`.xlsx`만 파싱
- 파싱 제외 파일을 반영 시 원본 첨부로 보관
- 전결권자에 `본부장`이 포함되면 `지역본부장`으로 정규화
- 실제 IT인프라 자원증설 `.xls`의 예외 원인 분석과 회귀 수정
- 부서별 파일 나열을 `파일 N건 · BLOCKER M건` 뱃지 버튼으로 교체
- 업로드 파일 목록을 폴더 구조로 보여주는 읽기 전용 다이얼로그
- 파일·폴더별 BLOCKER 개수와 파일 단위 진단 상세 펼침
- 메인 결과 테이블에서 수정 불가능한 진단 숨김

### 제외

- 분석 단계 파일 다운로드·선택 체크박스
- 저장된 반입 원본 파일 다운로드 다이얼로그의 계약 변경
- 서버의 진단 심각도·차단 판정·요약 계산 변경
- 지원 Excel 확장자 추가

## 용어와 판정

- **파싱 대상:** 파일 확장자가 대소문자 무관 `.xls` 또는 `.xlsx`이고, 확장자를 제외한 파일명에 `요청서`가 포함된 파일
- **원본 전용 파일:** 폴더 업로드에는 포함됐지만 파싱 대상이 아닌 파일. dry-run 결과를 만들지 않으며 commit 시 같은 archive group의 원본으로 보관한다.
- **수정 가능 진단:** `decision`이 `SELECT`, `TEXT`, `DATE`, `AMOUNT_UNIT` 중 하나인 진단
- **수정 불가능 진단:** `decision`이 `NONE`인 진단. 메인 결과 테이블에서는 숨기지만 파일 목록 다이얼로그에서 상세를 제공한다.
- **BLOCKER 개수:** 해당 파일 결과의 `severity=BLOCKER` 진단 수. 사용자가 결정으로 해소할 수 있는지와 무관하게 센다.

## 아키텍처

기존 백엔드 `RequestFormImportService`의 `archiveOnly` 경로와 프론트 `useRequestFormUpload`의 batching/progress를 유지한다. 파일 분류는 프론트 manifest 생성 시 적용해 불필요한 파싱 요청을 줄이고, 백엔드에서도 동일 규칙을 검증해 클라이언트 우회를 막는다.

프론트는 업로드 당시 `File[]`의 상대경로와 dry-run `FileResult[]`을 결합해 표시 전용 트리를 만든다. 저장된 공통파일 응답을 사용하는 `RequestFormSourceFiles`와 데이터 소스는 분리하되, 폴더 정규화·파일 아이콘 같은 순수 표현 유틸은 재사용한다. 분석 파일 다이얼로그는 다운로드나 선택 상태를 갖지 않는다.

## 진행 다이얼로그

진행 다이얼로그는 공통 상태 모델 `running | succeeded | failed`와 배치 완료 수·전체 수·진행률을 사용한다.

- dry-run 시작 전 Vue DOM을 한 번 flush한 뒤 요청을 시작한다.
- 분석 모드 제목은 `[편성요청서 분석]`, 실행 문구는 `파일 분석 중`으로 표시한다.
- 반영 모드 제목은 기존 `[편성요청서 반영]`을 유지한다.
- 실행 중에는 헤더·ESC·mask·푸터로 닫을 수 없다.
- 성공 시 분석한 파일/부서/차단 파일 요약을 보여주고 확인 버튼을 제공한다.
- 실패 시 마지막 완료 배치와 정제된 오류를 유지한다.
- 연속 실행은 이전 진행·오류·요약을 초기화한다.

## 파일 분류와 보관

프론트는 폴더 선택 직후 각 파일에 `archiveOnly`를 계산한다. 경로 안의 상위 폴더명에 `요청서`가 있어도 파일명 자체에 없으면 파싱하지 않는다. 예를 들어 `견적서.xlsx`는 요청서 폴더 아래 있어도 원본 전용이다.

백엔드는 manifest의 `archiveOnly=false` 항목이 파싱 대상 파일명 규칙을 만족하는지 다시 확인한다. 규칙을 만족하지 않으면 실패시키지 않고 원본 전용으로 취급한다. commit 시 기존 archive group 연결 규칙으로 함께 보관하고, dry-run 요약의 분석·차단 파일 수에는 포함하지 않는다.

## 실제 파일 파서 결함 분석

대상 파일:

`sample/2026/IT기획부(180)/_IT인프라팀/붙임2. 2026년 전산예산 편성 요청서(IT인프라팀)/04. (자본예산) IT인프라 자원증설/[자료1] 2026년 전산예산 편성 요청서_IT인프라 자원증설.xls`

구현 첫 단계에서 이 파일을 `WorkbookReader → FormSheetAdapter → preview` 경로로 통과시키는 로컬 샘플 회귀 테스트를 추가해 현재 런타임 예외와 최초 실패 리더·셀을 기록한다. 실 제출본은 저장소에 복사하거나 커밋하지 않고, 관측한 최소 레이아웃만 `RequestFormFixtures`에 비식별 POI fixture로 재현한다.

수정은 확인된 최초 원인에 한정한다. 경상사업 시트에 데이터 행이 1건뿐인 경우에도 행 범위·병합 셀·합계행 탐색이 빈 다음 행이나 잘못된 타입을 전제하지 않아야 한다. 유효한 경상사업 1건과 그 품목·금액은 preview에 생성되고 `FILE_UNREADABLE`로 치환되지 않아야 한다. 원인·수정 지점·회귀 테스트는 최종 보고에 남긴다.

## 전결권자 정규화

`FormApproverReader`가 읽은 전결권자 원문을 정규화할 때 문자열에 `본부장`이 포함되면 최종 값은 정확히 `지역본부장`이다. `지역본부장`, `○○본부장`, 공백이 섞인 표현도 같은 값으로 수렴한다. `부장`, `팀장` 등 `본부장`을 포함하지 않는 직책은 기존 규칙을 유지한다.

## 결과 화면과 파일 목록 다이얼로그

부서 결과 영역은 부서명과 진단 테이블 사이에 파일명을 직접 나열하지 않는다. 대신 부서명 옆에 읽기 가능한 버튼형 뱃지를 둔다.

- 기본 문구: `파일 {N}건`
- BLOCKER가 있으면: `파일 {N}건 · BLOCKER {M}건`
- 버튼에는 다이얼로그를 연다는 접근성 이름과 키보드 동작을 제공한다.

다이얼로그는 선택한 부서의 업로드 파일만 상대경로 폴더 트리로 표시하며 기본적으로 모든 폴더를 펼친다.

- 폴더 행: 폴더명, 하위 전체 파일 수, 하위 BLOCKER 수
- 파일 행: 확장자 아이콘, 파일명, 상태, 해당 파일 BLOCKER 수
- 파일 행 펼침: 수정 불가능한 WARNING/BLOCKER의 위치·메시지
- 수정 가능한 진단은 메인 결과 테이블에서 처리하므로 파일 상세에 중복 표시하지 않는다.
- 원본 전용 파일은 `분석 제외` 상태로 표시하고 진단 상세는 없다.
- 목록 확인 전용이므로 체크박스·다운로드 버튼은 제공하지 않는다.
- 표준 `AppDialogHeader`·`AppDialogFooter`와 닫기 버튼을 사용한다.

## 메인 진단 테이블

`RequestFormResultTable`은 `decision !== NONE`인 진단만 행으로 만든다. 파일의 서버 상태, 전체 BLOCKER 수, 반영 가능 여부는 원본 응답 기준을 유지한다. 수정 가능한 진단이 하나도 없는 파일은 진단 테이블에 빈 행을 만들지 않는다.

## 오류 처리

- 개별 파일 파서 예외는 현재처럼 배치 전체를 중단하지 않고 해당 파일 실패 결과로 변환한다.
- 분석 다이얼로그에는 서버 내부 예외를 직접 노출하지 않고 기존 정제 오류 문구를 사용한다.
- 파일 목록 상세에는 서버가 사용자용으로 생성한 진단 메시지만 표시한다.
- 파일명 규칙에서 제외된 파일은 오류나 경고가 아니라 `분석 제외`다.

## 테스트 전략

### 백엔드

- 파일명 `요청서` 포함/미포함, 대소문자 확장자, 폴더명만 포함하는 경계 테스트
- 조작된 manifest에서도 비대상 파일이 adapter로 전달되지 않는 서비스 테스트
- 비대상 파일이 commit archive plan에는 남는 테스트
- 실제 샘플 로컬 회귀와 비식별 최소 fixture 회귀
- 경상사업 1건의 사업·품목·금액 preview 검증
- `본부장` 포함 문자열의 `지역본부장` 정규화 테스트

### 프론트엔드

- 폴더 선택 시 분석 다이얼로그가 요청보다 먼저 렌더되는 테스트
- 분석/반영 제목·문구·성공 요약·닫기 제한 테스트
- manifest의 파싱 대상/원본 전용 분류 테스트
- 부서 뱃지의 파일/BLOCKER 집계 테스트
- 폴더·파일 펼침과 수정 불가능 진단 상세 테스트
- 목록 다이얼로그에 다운로드·체크박스가 없음을 검증
- 메인 결과 테이블이 `decision=NONE`을 숨기고 수정 가능한 진단은 유지하는 테스트

### 회귀

- 백엔드 focused tests 후 전체 `./gradlew test`와 영향 범위 `check`
- 프론트 focused Vitest 후 `format:check`, `check`, 전체 `npm test`, `lint:css`
- 실제 샘플 폴더 E2E에서 분석 진행 다이얼로그와 부서 파일 목록 확인

## 완료 조건

- 문제 파일이 `FILE_UNREADABLE` 없이 경상사업 1건을 preview한다.
- `요청서` 없는 Excel은 파싱되지 않지만 반영 원본에는 포함된다.
- `본부장` 포함 전결권자는 `지역본부장`으로 반환된다.
- 폴더 업로드 중 분석 진행 다이얼로그가 보이고 실행 중 닫히지 않는다.
- 부서 아래 파일명 나열이 사라지고 파일/BLOCKER 뱃지가 파일 목록 다이얼로그를 연다.
- 수정 불가능 진단은 메인 테이블에 없고 파일 상세 펼침에서 확인된다.
- 기존 저장 원본 다운로드와 반영 진행 흐름이 회귀하지 않는다.
