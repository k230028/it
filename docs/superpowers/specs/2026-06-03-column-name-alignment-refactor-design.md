# 컬럼명 정합 리팩토링 설계서

**작성일:** 2026-06-03
**상태:** 설계 승인됨 (구현 계획 대기)
**범위:** it_backend (엔티티/DTO/서비스/리포지토리/테스트) + it_frontend (타입/소비처)

---

## 1. 배경 및 목적

### 1.1 현황
이 시스템은 표준 메타 용어사전의 **물리 컬럼명**(예: `ABUS_MNG_NO`)을 사용하되,
애플리케이션 코드는 이를 **도메인 의미명**(예: `prjMngNo`)으로 재해석해 매핑한다.
즉 계층마다 명명 체계가 의도적으로 다른 상태이며, 다음 편차가 존재한다.

- **42개 엔티티 / 약 297개 필드**가 `lowerCamelCase(물리 컬럼명)` 규칙을 벗어남 (`*L` 로그 미러 포함).
- `BaseEntity`는 이미 규칙을 따름 (`DEL_YN`→`delYn`, `FST_ENR_DTM`→`fstEnrDtm`).

### 1.2 목적 — 거버넌스 준수
본 리팩토링의 근본 목적은 **데이터 거버넌스 준수**다. 사내 정보화 표준/감사 관점에서
"물리 표준명을 전 계층(엔티티·DTO·프론트)에서 일치"시키는 것이 요구된다.
따라서 개발 가독성 우려보다 **전 계층 명명 일치(완전성·정확성)**가 우선한다.

### 1.3 파일럿 근거 (이미 수행됨)
`project` 도메인을 컬럼명 규칙으로 전계층 리네임하는 파일럿을 완료하고 커밋했다
(백엔드 `d5d45c9`, 부팅오류 수정 `430d187`, 프론트 후속 정합). 파일럿에서 확인한 사실:

- **방식은 기계적**이나 **실패 모드가 컴파일 비가시적**이다 — Spring Data 파생 쿼리
  메서드명/JPQL이 옛 속성을 참조해도 `compileJava`는 통과하고 **부팅 시점**에
  `PropertyReferenceException`으로 실패했다. (예: `findAllByPrjMngNoInAndDelYn`)
- 부작용: 가독성 저하(`prjBg→rqmBgAmt`), 파생 표시필드 이중접미사 아티팩트(`bzDttNm→bzDttNmNm`),
  테이블 간 같은 컬럼 재사용에 따른 의미 충돌.

이 설계는 위 부작용을 **명명 규칙의 예외/조합 정책**으로 다루고, 컴파일 비가시 실패 모드를
**전용 스캐너 + 실기동 검증**으로 차단한다.

## 2. 명명 규칙

### 2.1 기준 규칙
모든 영속 필드명 = **`lowerCamelCase(물리 컬럼명)`**.
변환: 컬럼명을 `_`로 분리 → 첫 토큰 소문자, 나머지 토큰 첫 글자 대문자.

| 물리 컬럼 | 필드명 |
|---|---|
| `ABUS_MNG_NO` | `abusMngNo` |
| `SVN_DPM_C` | `svnDpmC` |
| `PRLM_HRK_OGZ_C_CONE` | `prlmHrkOgzCCone` |

**적용 대상:** 엔티티 `@Column` 필드, `@Id`/`@IdClass` 필드, `*L` 로그 미러 필드,
DTO 필드(요청+응답), 대응하는 프론트 TS 타입 필드 + JSON 키.
**불변(절대 변경 금지):** `@Column(name=...)`, 테이블명, DB 컬럼 — 이미 올바르므로 *코드*를 컬럼에 맞춘다.

### 2.2 예외 1 — 파생 표시필드 (`*Nm`)
조인으로 얻는 표시명(부서명·코드라벨 등)은 **물리 컬럼이 없으므로 거버넌스 대상이 아니다.**
- `{기반컬럼camel}Nm` 형태로 일관 유지 (예: `svnDpmCNm`).
- 퇴화된 이중접미사(`bzDttNmNm`)는 케이스별 정리. `BZ_DTT_NM`처럼 컬럼 자체가 이미 명칭을
  저장하는 경우, 중복 조인 표시필드는 제거한다.

### 2.3 예외 2 — 지역 변수/메서드 파라미터
API·영속 표면이 아니므로 범위 외. 사소한 경우만 기회적으로 정리.

### 2.4 예외 3 — 테이블 간 이름 충돌 (도메인 조합)
같은 물리 컬럼이 여러 엔티티에서 **다른 도메인 의미**로 재사용될 때
(예: `BG_NO` = Bbugtm 예산번호 / Bcostm IT관리비코드), 바로 `bgNo`로 통일하지 않는다.

**조합 규칙 (결정적):**
- 컬럼의 **의미상 주 소유 도메인**은 **원형 유지** (예: `BG_NO`의 주인 = 예산 도메인 Bbugtm → `bgNo`).
- 나머지 **재사용 도메인**은 **도메인 접두사 + 컬럼 camel** (예: Bcostm → `costBgNo`).

주 소유자 판정과 비소유자 접두사는 컬럼별로 **충돌 매핑표**(§3.1)에 명시하고 사전 승인한다.

## 3. 툴링

거버넌스 롤아웃의 핵심은 "재현 가능·감사 가능"이다. 도메인 적용 전에 도구를 먼저 구축한다.

### 3.1 충돌 매핑 분석기
42개 엔티티의 `@Column` 물리명을 전수 스캔 → 2개 이상 엔티티에 등장하는 **재사용 컬럼** 검출
→ 컬럼별 `{주 소유 엔티티 = 원형, 나머지 = 도메인접두사명}` **제안 맵** 생성.
사람이 검토·승인(거버넌스 산출물). 코드모드의 타깃 네임 소스가 된다.

### 3.2 코드모드 (리네임 적용기)
도메인별로 엔티티 필드 선언 + `@IdClass` 필드 + `*L` 미러 + DTO 필드 및 `from()/toEntity()` 매핑을
타깃 맵으로 리네임. Lombok이 게터/빌더를 재생성 → **컴파일 주도**로 호출부(`getOld()`/`.old(`)·
QueryDSL `Q*.old` 참조를 컴파일 에러 따라 정합(파일럿 검증 방식).

### 3.3 런타임 참조 스캐너 (가장 중요)
컴파일러가 못 잡는 참조를 전수 검출한다.

- Spring Data 파생 쿼리 메서드명: `findBy` / **`findAllBy`** / `existsBy` / `countBy` / `deleteBy` + 속성 토큰
  (`findAllBy` 변형은 파일럿에서 놓쳐 부팅오류를 유발한 케이스 — 반드시 포함)
- JPQL `@Query`(비-native)의 속성 경로 (`alias.oldField`)
- `Sort.by("…")` / `PageRequest` / QueryDSL `OrderSpecifier` 문자열 리터럴
- `@EntityGraph(attributePaths=…)` / `@NamedEntityGraph`
- 프론트 JSON 키: TS 타입 + 읽기/쓰기(payload)/표시(`*Nm`) 사용처
- **제외:** native `@Query`(컬럼명 사용) 및 바인드 파라미터명(`:prjMngNo`)

### 3.4 도메인 검증 하네스
`compileJava → 스캐너 → compileTestJava → bootRun(실기동) → (프론트) typecheck`를
한 번에 실행해 도메인별 pass/fail 리포트 생성.

## 4. 도메인별 검증 게이트

각 도메인은 다음을 모두 통과해야 커밋한다(하나라도 실패 시 중단·수정).

1. **타깃 맵 적용** — 충돌 매핑 반영, 엔티티+`*L`+`@IdClass`+DTO 리네임
2. **컴파일 주도 정합** — `compileJava` green (호출부·QueryDSL 참조 수정)
3. **런타임 스캐너** — 파생쿼리/JPQL/Sort/EntityGraph/프론트 키 잔존 참조 0
4. **테스트** — `compileTestJava` + 해당 도메인 단위/리포지토리 테스트 통과(목 메서드명 정합)
5. **실기동** — `bootRun`으로 Spring 컨텍스트 완전 초기화 확인
6. **프론트 락스텝** — 대응 타입·읽기/쓰기/표시 키 정합 → `typecheck` green
7. **원자적 커밋** — 도메인 1커밋(백엔드+프론트), 메시지에 변경 필드 맵 기록

---

## 5. 단계·순서

- **`project` 도메인 완료**(파일럿 = 기준 템플릿). 롤아웃은 여기서 이어간다.
- `*L` 미러는 마스터와 **함께** 리네임.
- **권장 순서:**
  1. 예산 잔여: `cost`·`plan`·`document`·`work`·`status`·`it` (project와 QueryDSL 강결합)
  2. `approval`·`board`·`code`·`iam`·`notification`·`system`
  3. `council`(다수 서브테이블)·`log`·`cdp`·`audit`·`infra`
- 게이트가 매 커밋마다 green+부팅을 보장하므로 순서는 유연(실패 시 해당 도메인 커밋만 영향).

---

## 6. 테스트 · 리스크 · 롤백

- **테스트:** 도메인별 기존 단위/리포지토리 테스트의 목 메서드명을 정합해 통과 유지.
  `bootRun`이 전체 파생쿼리·JPA 메타모델을 런타임 검증(컴파일 비가시 사각지대 차단).
  프론트는 `typecheck` + 핵심 화면 수동 QA.
- **API 계약:** 소비자는 내부 Nuxt 프론트 단일 → 백엔드+프론트 **하드 컷오버**(락스텝), 버전닝 불필요.
- **리스크/롤백:** 각 도메인 = 원자적 커밋 → 문제 시 해당 커밋만 revert(bisect 용이).
  충돌 매핑은 코드 착수 **전** 승인. 파생필드 예외는 문서화.

---

## 7. 거버넌스 산출물

1. **충돌 매핑표** — 재사용 컬럼별 주 소유자·비소유자 접두사명
2. **전체 컬럼↔필드 매핑표** — `it_backend/docs/guides/data-model.md`에 반영
3. **도메인별 커밋 이력** — 변경 필드 맵 포함, 감사 추적용

---

## 8. 비목표 (Out of Scope)

- DB 컬럼명/테이블명/타입 변경 (코드를 컬럼에 맞추는 것이 목적)
- 도메인 로직·API 엔드포인트 경로 변경
- 파생 표시필드(`*Nm`)의 물리명 강제(예외 처리)
- 컬럼명 자체의 결함(약어·재사용) 정비 — 별도 DB 거버넌스 과제
