# TASK 잔여과제 정리 설계

## 목적

`TASK.md`의 활성 과제 20건을 서로 독립적으로 검증할 수 있는 실행 묶음으로 나누고, 보안 및 실패 상태 결함을 우선 해소한 뒤 전체 Health Stack을 녹색으로 복구한다. 운영 DB 변경은 `meta/table.txt`, `meta/index.txt`, `meta/sequence.txt`를 기준으로 명명과 물리 계약을 확정하고 `meta/backlog.md`에 먼저 기록한다.

## 범위와 완료 조건

- 대상은 `SEC-21`~`SEC-23`, `BE-90`~`BE-100`, `FE-68`~`FE-73`, `CQ-42`~`CQ-44`다.
- 각 과제는 회귀 테스트, 영향 범위 검증, 문서 또는 OpenAPI 계약 갱신까지 끝났을 때만 `TASK_DONE.md`로 이동한다.
- `TEST.md`는 실행 결과 원문이므로 수정하지 않는다.
- 루트와 세 하위 저장소의 기존 미커밋 변경은 보존하며, 저장소별 커밋과 `versions.lock` 갱신을 분리한다.
- DB 변경은 신규 Flyway 버전, 적용 전 진단 SQL, 적용 후 검증 SQL, 운영 인계 문서를 한 묶음으로 취급한다.

## 실행 묶음과 순서

### 1. 현재 실패 중인 프론트 Health Stack 복구

`CQ-43`과 `CQ-44`를 먼저 고쳐 정적 검사와 타입 검사를 신뢰 가능한 상태로 되돌린다. 이어 `CQ-42`의 7개 초과 파일을 에디터, 상세 화면, 폼 화면 단위로 다시 나누며 예외 기준선은 추가하지 않는다. 대형 파일 분리는 동작 변경과 섞지 않고 기존 테스트를 특성 테스트로 보강한 뒤 진행한다.

### 2. 서버 권한 경계 복구

`SEC-21`과 `SEC-22`는 목록·건수·bulk·상세가 같은 actor 기반 부서 범위를 공유하도록 하나의 보안 계획으로 처리한다. `SEC-23`은 Q&A 목록에서 타 부서 비공개 행을 조회 술어로 제외하는 방식을 기본안으로 삼고, 제품상 자물쇠 행 유지가 필수일 때만 서버 DTO 마스킹으로 전환한다. 세 항목 모두 컨트롤러 테스트와 서비스/저장소 테스트에서 일반 사용자, 동일 부서, 타 부서, 관리자 경계를 고정한다.

### 3. DB 및 운영 안전성 정리

`BE-90`, `BE-95`~`BE-99`를 먼저 처리해 이후 백엔드 작업이 의존할 문서번호와 마이그레이션 계약을 확정한다.

- `BE-90`: 담당자 정보는 `CDOC-`, 공통 팝업은 `PDOC-`, 사업 가이드는 기존 `GDOC-`, 입력 길라잡이는 기존 `FDOC-`를 사용한다. 기존 특수 문서는 안정된 기술 키인 `DOC_TTL_CONE`로 한정해 개번하고, 연계 파일의 `CFILEM.APG_FL_LNK_CTZ_NM`이 문서번호를 참조하는 경우 함께 보정한다.
- 인덱스명은 `meta/index.txt`의 `IX_TPRMPP_{테이블약어}_{2자리 순번}` 규칙을 따른다. `TPRMPP_BGDOCM`의 기존 `_01` 뒤에 담당자 `_02`, 공통 팝업 `_03`, 사업 가이드 제목 `_04`를 배정한다.
- `BE-97`: 기존 계획의 충돌한 버전 번호를 실제 구현 시점의 다음 미사용 번호로 바꾸고 `IX_TPRMPP_BGDOCM_04`를 추가한다. 인덱스 생성 전에 활성 `GDOC-%` 제목 중복을 건수와 기술 키만으로 진단한다.
- `BE-95`, `BE-98`, `BE-99`: 이력 복구, 파괴적 DDL 소급 인계, 신규 테이블 검증 규약을 문서화한다. 현재 물리 구조를 다시 바꾸지 않는 문서 과제는 DDL 백로그에 허위 변경으로 넣지 않는다.
- `BE-96`: 이미 실행 순서상 앞에 있는 `V20260831_003`의 자동 절단을 후속 Flyway가 사전에 막을 수는 없다. 기존 환경은 절단 영향 감사와 복구 가능성 기록으로 다루고, 신규 환경은 DBA 사전 점검을 배포 게이트로 강제하거나 승인된 새 기준선을 제공한다. 별도 승인 없는 자동 데이터 절단 마이그레이션은 추가하지 않는다.

### 4. 백엔드 계약과 중복 정리

`BE-91`은 연도 중립 DTO와 기준연도 결정 계약을 먼저 정한 뒤 OpenAPI 소비자를 갱신한다. `BE-92`는 메타 명칭만 바로잡고 생성 타입을 재생성한다. `BE-93`은 100 BYTE 조직명 스냅샷에 같은 `Utf8ByteLimit` 경계를 적용한다. `BE-94`는 actor 검증을 서비스로 내리고 이력 데이터를 한 번에 조립한다. `BE-100`은 DB 문서 정리와 공통 문서번호 채번 헬퍼 추출을 앞선 DB 묶음 이후 수행한다.

### 5. 프론트 실패 상태와 소규모 정리

`FE-68`~`FE-70`은 정상 빈 값, 손상 입력, 조회 실패를 서로 다른 상태로 유지하고 재시도 경로를 테스트한다. `FE-71`은 생성 스키마 별칭으로 전환한다. `FE-72`는 결과가 완전히 같은 `escapeHtml`부터 공통화하고, 의미가 다른 `stripHtml`은 계약 테스트를 작성한 뒤 통합 여부를 결정한다. `FE-73`은 번역된 접근성 라벨을 호출부에서 주입한다.

### 6. 통합 검증과 과제 이동

백엔드는 `./gradlew test`, `./gradlew check`, `./gradlew bootJar`, 프론트는 `npm run format:check`, `npm run check`, `npm test`를 실행한다. API 계약 변경이 있는 묶음은 `npm run codegen`과 `npm run codegen:check`, 사용자 흐름 변경은 관련 Playwright 시나리오를 추가한다. DB 묶음은 Flyway 적용 전후 검증과 `flyway_schema_history`를 확인한다. 완료된 ID만 `TASK_DONE.md`에 근거와 검증 결과를 기록하고 `TASK.md`에서 제거한다.
