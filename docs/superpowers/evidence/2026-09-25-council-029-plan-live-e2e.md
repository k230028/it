# COUNCIL-029 정보기술부문계획 협의회 오픈 전 검증

검증일: 2026-09-25  
대상: 정보화실무협의회 02 유형(정보기술부문계획을 위한 정보화실무협의회)  
환경: 로컬 프론트엔드, 로컬 백엔드(`local-ext`), 로컬 Oracle

## 결과

- 실제 계획 스냅샷 1건과 심의 대상 정보화사업 8건으로 신규 협의회를 생성했다.
- 신청(01) → 개최준비(05) → 일정확정(06) → 진행중(07) → 평가작성중(08) → 결과작성(09) → 결과검토(10) → 검토완료(11) → 결재중(12) → 완료(13) 전이를 확인했다.
- 기본 당연위원 7명이 중복 없이 편성되고 IT기획팀장 당연위원·간사 겸직(04)이 1명인 것을 확인했다.
- 7명 전원의 일정 제출 전 일정 확정 거부, 02 유형 서면개최 거부, 비위원 평가 제출 거부를 확인했다.
- 모든 위원이 8개 사업을 평가하기 전 완료 처리가 거부되고, 전원 평가 후 완료되는 것을 확인했다.
- 한 위원의 유보가 사업 최종 유보로 집계되고 사업별 평가자 수가 7명으로 계산되는 것을 확인했다.
- 결과서 생성·확정, 위원 7명 전원 검토, 팀장·부장 순차 결재를 거쳐 완료(13)까지 진행했다.
- 완료 뒤 일정·사업평가·결과서 수정 요청이 모두 409로 거부되는 것을 확인했다.
- 보완 뒤 실제 완료 화면이 렌더링되고 위원 검토 섹션 컴포넌트 미해석 경고가 0건인 것을 확인했다.
- 실제 API·브라우저 종단 검증 89단계가 모두 통과했다. 식별값·계정·실행 원본은 저장소 밖 `.tmp/council-local`에 보관했다.

## 발견 및 보완

1. 서버가 평가위원 일정 미응답 상태에서도 관리자의 일정 확정 요청을 허용했다. 전원 제출 여부를 서버에서 검사하도록 보완했다.
2. 02 유형이 서버 API로 서면개최될 수 있었다. 02 유형은 대면개최만 허용하도록 서버에서 차단했다.
3. 개최준비(05)가 지난 뒤에도 위원이 일정을 다시 저장할 수 있었다. 원장 잠금과 상태 검사를 일정 저장에 적용했다.
4. 결과검토(10) 화면의 검토 섹션 컴포넌트 이름이 실제 파일명과 달라 브라우저에서 해석되지 않았다. 컴포넌트를 명시적으로 import하고 실제 이름으로 렌더링하도록 수정했다.

## 자동화 검증

- 백엔드 집중 테스트: `ScheduleServiceTest`, `CouncilServiceTest`, `PlanEvaluationServiceTest`, `CouncilPlanSnapshotTest`, `CommitteeServiceTest` 통과.
- 프론트 단위 테스트: 계획 예산·통계·결과 화면 및 접근 판정 관련 17건 통과.
- 계획 스냅샷 손상 배너 Mock E2E 2건 통과.
- 기존 계획평가 Mock E2E 1건은 로컬 서버 중복 실행 환경에서 인증 Mock이 SSR 요청에 적용되지 않아 실패했다. 동일 제출 흐름은 실제 브라우저·백엔드·Oracle 종단 검증에서 7명 × 8개 사업으로 통과했다.
