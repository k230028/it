## 1. Overview

### 1.1 Design Goals

- **분리**: 신규 기능 로직(전년도 피커, 중복 체크, 예산탭 컬럼)을 독립 composable로 추출하여 기존 파일 비대화 방지
- **최소 백엔드 변경**: FR-01~04 컬럼 재구성은 기존 API 필드(`reqTotalBg`, `adjTotalBg`)만 활용하여 백엔드 무변경; FR-05·10만 DTO 확장
- **이중 접근 제어**: FR-09는 프론트 미들웨어 + 백엔드 SecurityConfig 동시 적용 (CLAUDE.md §4.8 원칙)

### 1.2 Design Principles

- 신규 로직은 composable/component로 분리, pages는 레이아웃과 연결만 담당
- 공통코드명 조회는 `useCodeOptions` 재활용 (캐싱 내장)
- 기존 `saveAndExitEdit` 흐름은 유지하고 중복 체크 레이어를 앞에 삽입

#### PlanCreatePayload 확장 (FR-10)
```typescript
// pages/info/plan/form.vue — createPlan 호출 시 확장 페이로드
interface PlanCreatePayload {
  plnYy: string;
  plnTp: string;
  prjMngNos: string[];
  itMngcNos: string[];
  // ← 신규: 예산 배분 상세
  budgetAllocation?: BudgetAllocationItem[];   // 비목별 편성액
  capitalBudget?: CapitalBudgetItem[];          // 신규/계속 구분 자본예산
  expenseCost?: ExpenseCostItem[];              // 일반관리비 세목별 집계
}

interface BudgetAllocationItem {
  ioeC: string;       // 비목코드
  ioeCNm: string;     // 비목명
  allocBg: number;    // 편성금액
}

interface CapitalBudgetItem {
  pulDtt: string;     // PUL_DTT_001(신규)/PUL_DTT_002(계속)
  pulDttNm: string;
  assetBg: number;
}

interface ExpenseCostItem {
  dupIoe: string;     // DUP_IOE 구분코드
  dupIoeNm: string;
  ioeC: string;       // IOE-239-0200 세목코드
  ioeCNm: string;
  costBg: number;
}
```

### 3.2 백엔드 DTO 변경

#### CostDto.ListResponse — FR-05 prevBgAmt 추가
```java
// it_backend/.../cost/dto/CostDto.java
// ListResponse 레코드에 필드 추가
public record ListResponse(
    String itMngcNo,
    String pulDtt,
    // ... 기존 필드 유지 ...
    BigDecimal prevBgAmt   // ← 신규: PUL_DTT_002(계속)이면 전년도 costBg 합계, 신규면 BigDecimal.ZERO
) {}
```

**서버 계산 로직**: `CostService` 또는 `CostQueryRepositoryImpl`에서
- `pulDtt = 'PUL_DTT_002'`(계속): 동일 `itMngcNo`의 `bgYy-1` 레코드의 `cost_bg` 합계 조회
- 기타: `BigDecimal.ZERO` 반환

#### PlanDto.CreateRequest 확장 — FR-10
```java
// it_backend/.../plan/dto/PlanDto.java
public record CreateRequest(
    String plnYy,
    String plnTp,
    List<String> prjMngNos,
    List<String> itMngcNos,
    // ← 신규 필드 (nullable)
    List<BudgetAllocationItem> budgetAllocation,
    List<CapitalBudgetItem> capitalBudget,
    List<ExpenseCostItem> expenseCost
) {}
// BudgetAllocationItem, CapitalBudgetItem, ExpenseCostItem은 inner record로 정의
// PlanDto.SnapshotDto에도 동일 필드 추가하여 plnDtlCone JSON에 포함
```

### 3.3 BudgetStatusDto.CostResponse — 변경 없음

FR-01~03에서 사용할 필드는 이미 존재:
- `reqTotalBg`: 2025년(전년도) 편성금액 합계
- `adjTotalBg`: 2026년(당해연도) 편성금액 합계
- 증감: `adjTotalBg - reqTotalBg` (프론트 computed로만 처리)
- 세부 비목 필드(`reqRentBg` 등 8개)는 프론트에서 컬럼 제거만 하면 됨
