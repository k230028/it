### 1.4 판정 규칙 (직전 회차 유지)

- PK 컬럼은 Oracle에서 PK 제약이 `NOT NULL`을 강제하므로 NULL 제약 비교에서 제외합니다(3.7).
- 로컬의 `DEFAULT NULL`은 기본값 미지정과 동작이 같으므로 정규화하여 Gap으로 집계하지 않습니다(3.11).

## 4. 이번 비교로 확인할 수 없는 항목

운영 기준 파일에 정보가 없어 판정 대상에서 제외했습니다. 직전 회차 대비 **인덱스 항목이 빠졌습니다**(3.12).

- **문자 길이 semantics (`CHAR` / `BYTE`)** — 운영은 길이 숫자만 제공합니다.
  로컬은 `VARCHAR2` 1,143개 중 **950개가 `CHAR`, 193개가 `BYTE`**이며 **38개 테이블이 혼용**합니다.
  직전 회차(845/294, 51테이블) 대비 `CHAR`가 105개 늘었는데, `V20260823_002`가 30개 테이블 100개
  컬럼을 전환한 결과입니다(`docs/operations/2026-08-23-char-semantics-alignment-handover.md`).
  **`TPRMPP_BTERMM`·`BTERML`의 `SVN_DPM_NM`·`SVN_TEM_NM` 4개는 `BYTE`로 유지**하는 것이
  결정 사항이며(`docs/operations/2026-08-29-terminal-org-name-byte-semantics.md`), 이번 재생성에서도
  `CHAR_USED='B'`를 그대로 지켰습니다(5.2).
- **정밀도 미지정 `NUMBER` 여부** — 운영은 `TPRMPP_CLOGNH.LGN_LOG_SNO`와 `TPRMPP_CRTOKM.LGN_LOG_SNO`를
  `NUMBER` 길이 `22`로 적었고 로컬은 `NUMBER(22,0)`입니다. 정밀도 미지정 `NUMBER`의 `DATA_LENGTH`도
  22이므로 운영 추출본만으로는 구분할 수 없습니다.
- **FK, CHECK 제약, UNIQUE 제약** — 운영은 PK 여부와 인덱스만 제공합니다. 로컬에는 **FK가 0개**이고
  (라이브 DB 확인) CHECK 제약 17개가 있습니다. `CK_CLANGM_DTT_COL`의 운영 반영 여부는 여전히 미확인입니다.
- **뷰, 트리거, 프로시저, 시노님, 타입** — 운영 기준 파일에 없습니다.
- **컬럼 순서·기본값의 운영 실제값** — 1.3의 이유로 `meta/table.txt` 값이 운영 DB 물리 상태와 다를 수
  있습니다. 3.9의 정렬 판단이 여기에 걸려 있습니다(5.1).
- **인덱스의 운영 실제 존재 여부** — `meta/index.txt`도 신청서 성격이라(1.3), 등록된 70건이 운영 DB에
  실제로 생성돼 있는지는 이 파일만으로 확정할 수 없습니다.

### 5.1 컬럼 순서를 정의서 기준으로 정렬한 근거

운영 접근 경로는 이번에도 없었지만, **정렬을 보류하지 않고 진행한 근거가 세 가지 있습니다.**

1. **지시문이 명시적으로 정렬을 요구**합니다("완전히 일치시켜줘").
2. **정의서 순서가 스키마 내 기존 관례와 같습니다.** `SVN_DPM_NM`·`SVN_TEM_NM`을 대응 코드 컬럼

   운영 물리 순서와 무관하게 **로컬 스키마 자체의 일관성을 높입니다.**
3. **비용이 낮습니다.** 대상 3개 테이블의 행 수가 `TPRMPP_BTERMM` 0, `TPRMPP_BTERML` 1,

**만약 운영 물리 순서가 정의서와 다르다면**(즉 운영도 `ALTER TABLE ADD`로 끝에 붙였다면) 이번 정렬은
운영과의 Gap을 오히려 만든 셈이 됩니다. 6.2의 실측 확인이 여전히 필요한 이유입니다. 다만 그 경우에도

직전 회차 5.4가 권고했으나 미착수였고, **그 사이 같은 유형의 Gap 37건이 재발**했습니다(3.9.1).
`it_database/CLAUDE.md` 2장 또는 `docs/guides/migrations.md`에 다음을 남기기를 권합니다.

- **감사 컬럼 블록** — `FST_ENR_USID`, `FST_ENR_DTM`, `DEL_YN`, `GUID`, `GUID_PRG_SNO`,
  `LST_CHG_USID`, `LST_CHG_DTM`을 이 순서로 테이블 끝에 둡니다. 변경로그 테이블은 그 앞에

- **신규 업무 컬럼은 `ALTER TABLE ADD`만으로 끝내지 않습니다.** Oracle에서 컬럼 추가는 반드시
  테이블 끝에 놓여 위 규약을 깹니다. 업무 컬럼을 추가할 때는 (a) 같은 마이그레이션에서 테이블을
  재생성하거나, (b) 순서 Gap이 생김을 인지하고 후속 정렬 마이그레이션을 함께 계획합니다.
- **인덱스 명명** — `IX_{테이블명}_{2자리 일련번호}`. UNIQUE 여부를 접두사로 표현하지 않습니다(3.12).
  설계 문서에 임의 이름을 적기 전에 `meta/index.txt`의 다음 번호를 확인합니다.
- **시퀀스 표준** — 로그 시퀀스 `MAXVALUE 999999999999999000`, 기본 테이블 시퀀스 `MAXVALUE 9999`
  (+`CYCLE`). `CACHE 20`, `NOORDER`.

### 6.2 운영 실측 확인 (4장, 5.1)

운영 DB에 읽기 접근이 열리면 다음 한 번으로 4장 미확인 항목 대부분이 해소됩니다.

```sql
SELECT column_id, column_name, data_type, data_length, char_length, char_used,
       nullable, data_default
  FROM all_tab_columns
 WHERE owner = 'ITPOWN'
   AND table_name IN ('TPRMPP_BTERMM', 'TPRMPP_BTERML', 'TPRMPP_CFILEM')
 ORDER BY table_name, column_id;

SELECT index_name, table_name, uniqueness, index_type
  FROM all_indexes
 WHERE owner = 'ITPOWN' AND generated = 'N'
 ORDER BY index_name;
```

첫 쿼리로 컬럼 순서(5.1의 잔여 리스크)·기본값 실제값·`CHAR`/`BYTE`가, 둘째 쿼리로
