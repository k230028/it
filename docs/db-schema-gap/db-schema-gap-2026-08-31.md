# 운영·로컬 DB Gap 분석 결과 (2026-08-31)

## 1. 결론

**운영에서 변경이 필요한 부분 0건, 로컬에서 변경이 필요한 부분 0건입니다.**

비교 가능한 8개 항목(시퀀스명·시퀀스 속성·테이블명·테이블 코멘트·컬럼명·컬럼 타입·컬럼 순서·컬럼
코멘트)과 추가 3개 항목(PK·NULL 제약·인덱스) 전부에서 실질 Gap이 없습니다. 직전 회차(2026-08-29)에
적용한 컬럼 순서 정렬 47건과 인덱스명 변경 2건이 유지되고 있고, 그 이후 새로 벌어진 항목도 없습니다.

남는 것은 **표기 차이 31건 + 런타임 카운터 62건**뿐이며 전부 조치 불필요로 확정한 항목입니다(4장).

## 2. 비교 기준

| 입력 | 기준 | 비고 |
| --- | --- | --- |
| `meta/table.txt` | 루트 `bb53b8d` | 1,685줄 = 헤더 1 + 컬럼 1,684 |
| `meta/sequence.txt` | 루트 `e853680` | 63줄 = 헤더 1 + 시퀀스 62 |
| `meta/index.txt` | 루트 `393c995` | 71줄 = 헤더 1 + 인덱스 70 |
| `it_database/ITPOWN_DDL_live.sql` | `it_database` `16f77f4` | `Generated at: 2026-08-31 00:09:06 +09:00` |

- 제외: `FLYWAY_SCHEMA_HISTORY` (양쪽 모두)
- 운영 기준 파일 3개는 직전 회차와 **동일 커밋**입니다. 즉 운영 기준선은 바뀌지 않았습니다.
- 로컬 스냅샷만 재추출됐습니다. 직전 스냅샷과의 diff는 **시퀀스 카운터 15건과 `Generated at` 한 줄이
  전부**이며 구조 변경은 0건입니다.
- 판정 규칙은 직전 회차를 유지합니다 — Oracle에서 동작이 같은 표기 차이(`DEFAULT NULL` vs 기본값 없음,
  PK가 강제하는 `NOT NULL`)는 Gap으로 집계하지 않습니다.

### 2.1 스냅샷이 마이그레이션 기준선과 맞습니다

`V20260829_002` 이후 추가된 마이그레이션은 `V20260829_003`·`V20260829_004`·`V20260830_001`~`003`
5건이고 **전부 시드 데이터 전용**입니다(`CREATE`/`ALTER`/`DROP`/`RENAME` 문 0건). 구조를 바꾸는
마이그레이션이 없으므로 2026-08-31 00:09 스냅샷은 구조 기준으로 최신입니다.

### 2.2 운영 기준 파일은 정의서·신청서입니다

`meta/*.txt`는 운영 DB에서 직접 뽑은 데이터 사전이 아니라 설계 정의서와 인덱스 신청서입니다.
따라서 "운영 변경 필요 0건"은 **정의서와 로컬이 일치한다**는 뜻이고, 운영 DB 물리 상태와의 일치는
5장의 실측으로만 확정됩니다. 이 한계는 직전 회차와 동일합니다.

## 4. 조치 불필요로 확정한 차이 (합계 93건)

| 구분 | 건수 | 근거 |
| --- | ---: | --- |
| `DEFAULT NULL` 표기 | 29 | 운영은 "기본값 없음", 로컬은 `DEFAULT NULL`. Oracle에서 동작이 같고 운영 추출본이 두 표기를 구분하지 못해 정렬 목표를 정의할 수 없음. 13개 테이블, 직전 회차와 동일 |
| PK에 가려진 `NOT NULL` | 2 | `TPRMPP_CRTOKM.LGN_LOG_SNO`, `TPRMPP_CUSERI.ENO`. 별도 `NOT NULL` 제약 없이 PK만 걸려 있어 `DBMS_METADATA`가 `NOT NULL ENABLE`을 쓰지 않음. PK가 `NULL`을 막으므로 동작 동일 |
| 시퀀스 현재값 | 62 | 런타임 카운터로 스키마 정의가 아님. **62건 전부 로컬이 운영보다 큼**(로컬 < 운영 0건). 로컬을 운영 값으로 낮추면 이미 채번된 행과 `ORA-00001` 충돌 |

시퀀스 현재값 상위 차이: `SQ_TPRMPP_CRTOKM_1`(운영 201 / 로컬 4,822), `SQ_TPRMPP_CLOGNH_1`(101 /
3,845), `SQ_TPRMPP_CFILEM_1`(41 / 3,518). 운영 값이 `1`/`21`/`41`/`81`/`101`/`201`처럼 `20k+1`
형태만 나오는 것은 `CACHE 20` 선점의 결과입니다.

## 5. 이번 비교로 확인할 수 없는 항목

운영 기준 파일에 정보가 없어 판정 대상에서 제외했습니다. 직전 회차와 동일합니다.

- **문자 길이 semantics (`CHAR`/`BYTE`)** — 운영은 길이 숫자만 제공. 로컬 `VARCHAR2` 1,143개 중
  `CHAR` 950 / `BYTE` 193이며 38개 테이블이 혼용합니다. `TPRMPP_BTERMM`·`BTERML`의
  `SVN_DPM_NM`·`SVN_TEM_NM` 4개를 `BYTE`로 유지하는 것은 결정 사항입니다
  (`docs/operations/2026-08-29-terminal-org-name-byte-semantics.md`).
- **정밀도 미지정 `NUMBER` 여부** — 운영은 `TPRMPP_CLOGNH.LGN_LOG_SNO`·`TPRMPP_CRTOKM.LGN_LOG_SNO`를
  `NUMBER` 길이 22로 적었고 로컬은 `NUMBER(22,0)`입니다. 정밀도 미지정 `NUMBER`의 `DATA_LENGTH`도
  22라 운영 추출본만으로는 구분 불가.
- **FK·CHECK·UNIQUE 제약** — 운영은 PK와 인덱스만 제공. 로컬 스냅샷에는 CHECK 제약 17개(`CK_` 접두사)가
  있고 FK는 0개입니다(FK 0개는 직전 회차 라이브 DB 확인 결과이며, 이후 구조 마이그레이션이 없어 유효).
- **뷰·트리거·프로시저·시노님·타입** — 운영 기준 파일에 없음. 로컬에는 뷰 1개(`V_ITPAPP_LOG_FEED`),
  나머지는 0개.
- **컬럼 순서·기본값·인덱스의 운영 실제 물리 상태** — 2.2의 이유로 정의서 값이 운영 DB와 다를 수 있음.

## 6. 남은 권고

### 6.1 감사 컬럼 배치·명명 규약 문서화 — 미착수 (최우선)

직전 두 회차가 연속으로 권고했으나 `it_database/CLAUDE.md`와 `it_database/docs/guides/migrations.md`
어디에도 아직 없습니다. 이번 회차 Gap이 0인 지금이 규약을 고정하기 좋은 시점입니다. 규약이 없으면
다음 `ALTER TABLE ADD` 한 번으로 컬럼 순서 Gap이 다시 생깁니다(직전 회차 재발 37건).

- **감사 컬럼 블록** — `FST_ENR_USID`, `FST_ENR_DTM`, `DEL_YN`, `GUID`, `GUID_PRG_SNO`,
  `LST_CHG_USID`, `LST_CHG_DTM`을 이 순서로 테이블 끝에 둡니다. 변경로그 테이블은 그 앞에
  `CHG_DTT_YN`, `CHG_DTM`, `CHG_USID`가 옵니다. 업무 컬럼은 전부 그 앞입니다.
- **신규 업무 컬럼은 `ALTER TABLE ADD`만으로 끝내지 않습니다.** Oracle에서 컬럼 추가는 반드시 끝에
  붙어 위 규약을 깹니다. 같은 마이그레이션에서 테이블을 재생성하거나, 후속 정렬 마이그레이션을 함께
  계획합니다.
- **인덱스 명명** — `IX_{테이블명}_{2자리 일련번호}`. `UNIQUE` 여부를 접두사로 표현하지 않습니다
  (정의서 70건 중 `UX_` 0건, UNIQUE 6건도 전부 `IX_`).
- **시퀀스 표준** — 로그 시퀀스 `MAXVALUE 999999999999999000`, 기본 테이블 시퀀스 `MAXVALUE 9999`
  (+`CYCLE`). 공통 `CACHE 20`, `NOORDER`.

### 6.2 운영 실측 확인 (5장)

운영 DB 읽기 접근이 열리면 아래 두 쿼리로 5장 미확인 항목 대부분이 해소됩니다. 결과는 접속정보·
비밀값 없이 기록합니다.

```sql
SELECT column_id, column_name, data_type, data_length, char_length, char_used,
       nullable, data_default
  FROM all_tab_columns
 WHERE owner = 'ITPOWN'
 ORDER BY table_name, column_id;

SELECT index_name, table_name, uniqueness, index_type
  FROM all_indexes
 WHERE owner = 'ITPOWN' AND generated = 'N'
 ORDER BY index_name;
```

## 7. 재현 방법

비교 도구는 스크래치 경로의 일회성 Python 스크립트이며 커밋 대상이 아닙니다. 입력 4개는 2장 표와
같고 양쪽에서 `FLYWAY_SCHEMA_HISTORY`를 제외합니다. 정규화 규칙 3가지가 판정에 필요합니다.

- 정의서의 `소수점` 공란은 `NUMBER` 소수점 `0`으로 읽습니다(공란 스케일 표기).
- 로컬 `VARCHAR2(n CHAR)`와 `VARCHAR2(n)`은 길이 `n`으로 같게 봅니다(운영이 semantics 미제공, 5장).
- FBI 식은 따옴표와 공백을 제거해 대조합니다.
