### 1.3 운영 테이블 기준 파일의 정의서 성격 — 이번 회차 추가 근거

직전 회차 1.4의 판단이 이번 추가분으로 한 번 더 뒷받침됩니다. **`APG_FL_PTH`가 `APG_FL_SZ`와

반드시 테이블 끝에 놓이므로, 이 파일의 행 순서는 물리 컬럼 순서가 아니라 정의서상 논리 순서입니다.

`Default Value` 열에 `NULL` 표기가 0건인 점도 그대로입니다(`sysdate` 184, `'00000000000000'` 184,
`0` 94, `'N'` 94, `'000…0'` 92, `'10'` 2, `'Y'` 1, `'LEGACY'` 1).

따라서 **컬럼 순서는 이번에도 "운영 DB 실제 물리 순서"가 아닌 "정의서 순서"와의 비교**로 읽어야

형식입니다.

### 1.4 판정 규칙 (직전 회차 유지)

- PK 컬럼은 Oracle에서 PK 제약이 `NOT NULL`을 강제하므로 NULL 제약 비교에서 제외합니다(3.7).
- 로컬의 `DEFAULT NULL`은 기본값 미지정과 동작이 같으므로 정규화하여 Gap으로 집계하지 않습니다(3.11).
- `VARCHAR2` 길이는 숫자만 비교합니다. 운영 추출본에 `CHAR`/`BYTE` semantics 정보가 없습니다(4장).
- `NUMBER`의 운영 길이 `22`는 로컬 `NUMBER(22,0)`과 구분 불가이므로 일치로 봅니다. 운영의 빈 소수점은 `0`으로 정규화합니다.
- 시퀀스 현재값은 런타임 카운터이므로 스키마 Gap으로 집계하지 않습니다(3.10.2).

## 4. 이번 비교로 확인할 수 없는 항목

운영 기준 파일에 정보가 없어 판정 대상에서 제외했습니다.

- **문자 길이 semantics (`CHAR` / `BYTE`)** — 운영은 길이 숫자만 제공합니다.
  로컬 스냅샷은 `VARCHAR2` 1,139개 중 **845개가 `CHAR`, 294개가 `BYTE`**(세션 기본값이라 미표기)이며
  **51개 테이블이 두 방식을 혼용**합니다. 직전 회차(837/294, 51테이블) 대비 `CHAR`가 8개 늘었는데,
  재생성으로 만들어진 신규 컬럼 8개(`CGPR_NM` 4, `TLR_NM` 2, `USR_NM` 2)입니다.
  **`V20260820_011`이 반영되면 `CFILEM.FL_NM`·`APG_FL_PTH` 2건이 `BYTE`→`CHAR`로 옮겨가
  847/292가 됩니다**(1.1). AL32UTF8에서 한글 저장 한도가 달라지는 축이라 별도 확인이 필요합니다.
- **정밀도 미지정 `NUMBER` 여부** — 운영은 `TPRMPP_CLOGNH.LGN_LOG_SNO`와 `TPRMPP_CRTOKM.LGN_LOG_SNO`를
  `NUMBER` 길이 `22`로 적었고 로컬은 `NUMBER(22,0)`입니다. 정밀도 미지정 `NUMBER`의 `DATA_LENGTH`도
  22이므로 운영 추출본만으로는 구분할 수 없습니다. 1.4에 따라 미집계했습니다.
- **인덱스, FK, CHECK 제약, UNIQUE 제약** — 운영은 PK 여부만 제공합니다. 로컬에는 인덱스 **70개**,
  CHECK 제약 **17개**가 있습니다(직전 회차와 동일). `UX_TPRMPP_CMFATM_01`(`APN_CER_CRTT_TOK_CONE`
  UNIQUE)과 `CK_CLANGM_DTT_COL`은 운영 반영 여부가 기능에 직접 영향을 주는데 여전히 미확인입니다.
- **뷰, 트리거, 프로시저, 시노님, 타입** — 운영 기준 파일에 없습니다. 로컬에는 뷰 1개
  (`V_ITPAPP_LOG_FEED`), 트리거·프로시저·패키지 0개입니다.
- **컬럼 순서·기본값의 운영 실제값** — 1.3의 이유로 `meta/table.txt` 값이 운영 DB 물리 상태와 다를 수
  있습니다. 3.9의 판단이 여기에 걸려 있습니다.
- **로컬 DB의 마이그레이션 적용 여부** — 1.1의 이유로 `V20260820_011`·`012`가 실제로 적용됐는지
  스냅샷만으로는 알 수 없습니다.

### 5.2 운영 실측 확인 — `TPRMPP_CFILEM` 컬럼 순서 (3.9)

**로컬을 고치기 전에 운영 DB의 실제 물리 순서를 확인**하십시오. 3.9에서 적었듯 운영도
`ALTER TABLE ... ADD`로 붙였다면 물리 순서는 로컬과 같은 마지막이고, 이 경우 **Gap 자체가 없으며
`meta/table.txt`의 행 위치만 조정하면 됩니다.**

```sql
SELECT column_id, column_name, data_type, data_length, char_used, nullable, data_default
  FROM all_tab_columns
 WHERE owner = 'ITPOWN' AND table_name = 'TPRMPP_CFILEM'
 ORDER BY column_id;
```

결과에 따른 조치입니다.

| 운영 `APG_FL_PTH`의 `column_id` | 판정 | 조치 |
| ---: | --- | --- |
| 16 (마지막) | Gap 없음 — 정의서 표기 차이 | `meta/table.txt`에서 해당 행을 `LST_CHG_DTM` 뒤로 이동 요청. 로컬 무변경 |
| 7 | 실질 Gap | `TPRMPP_CFILEM` 재생성 마이그레이션 작성 (5.0 결정 적용) |

재생성을 택할 경우 비용을 감안해야 합니다. `TPRMPP_CFILEM`은 첨부파일 메타 테이블이라 행이 계속
늘고 있고(직전 회차 적용 시점 1,374행), 재생성 중 업로드가 들어오면 유실됩니다. 직전 회차처럼
사용이 없는 시간대에 하고, 적용 후 행 수와 최소 `FST_ENR_DTM`을 대조하십시오.

같은 쿼리로 `data_default`와 `char_used`도 함께 받아 두면 4장의 미확인 항목 2개(기본값 실제값,
`CHAR`/`BYTE`)가 한 번에 해소됩니다.

## 6. 재현 방법

```bash
node "C:/Users/KDB/AppData/Local/Temp/claude/C--it/4417537e-7231-452b-855f-a6c4fcea8d7e/scratchpad/gap.js" gap.json
```

스크립트는 세션 스크래치 경로에 있고 커밋 대상이 아닙니다. `GAP_ROOT` 환경변수로 입력 루트를 바꿔
과거 회차를 재현할 수 있습니다(1.5에서 사용). 입력 3개는 `{GAP_ROOT}meta/table.txt`,
`{GAP_ROOT}meta/sequence.txt`, `{GAP_ROOT}it_database/ITPOWN_DDL_live.sql`입니다.

**파싱 주의점 4가지**입니다.

- `DBMS_METADATA` 출력의 컬럼 정의는 **한 줄로 끝나지 않을 수 있습니다.** 제약 절이 여러 줄에
  걸치므로 `CONSTRAINT`/`USING INDEX` 시작 라인을 누적해서 괄호가 닫힐 때까지 이어 붙여야 합니다.
- `TIMESTAMP (6)`처럼 **타입명과 괄호 사이에 공백**이 들어갑니다. 공백을 제거한 뒤 비교합니다.
- `NOCYCLE`/`NOORDER`/`NOCACHE`를 `CYCLE`/`ORDER`/`CACHE`보다 **먼저** 판정해야 합니다.
  단순 부분 문자열 매칭은 `NOCYCLE`을 `CYCLE`로 잘못 읽습니다.
- 운영 `NULL여부` 열은 **`Y`가 NULL 허용, `N`이 `NOT NULL`**입니다. 로컬의 `NOT NULL ENABLE` 유무와
  방향이 반대이므로 뒤집어 비교합니다.
